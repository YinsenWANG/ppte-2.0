## 远程开发执行规则

1. 优先开发新方案，不必先在即将退休的旧渲染器或旧编辑器里把所有问题修一遍。
2. 如果一段旧代码仍被新版调用，它上面的缺陷依然属于新版缺陷，不能用“计划退休”豁免。
3. 如果旧路径已完全从新发行包和调用链退出，旧路径专属问题可以记为“范围退休”，但必须证明新路径满足对应用户需求。范围退休和修复通过要分开记录。
4. R01、R02 以及保存不丢内容等用户可见要求，只有在实际新版中复验通过才能关闭；设计稿、菜单隐藏和任务状态修改都不是修复证据。
5. 下一次回交按 R01–R06 分别填写：对应新提交、实际验证、已退出的旧范围、仍未通过的部分；再按 H00–H06 报告新功能状态。
