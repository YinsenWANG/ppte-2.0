另复验前轮12页原生作者稿：h1 有字体控件，添加页实际鼠标可点击，计数达到13。这区分了特定标签修复与广泛 HTML 支持。图片输入使用生成的截图，仅作为可重复插入素材，不冒充用户图片语义理解。

实际安装版 Chrome 152.0.7977.76，headless、file://、离线；独立旅程无脚本错误与 HTTP 请求。本轮没有原生文件授权写回验证；点击保存后的取消状态不能当作成功授权或保存失败。版本命名的 prompt 由自动化接受，其类型是真实产品调用记录。

## R1 · P1：原生 div 文本无法编辑或设置文字样式

操作：打开同原型样稿→编辑→点击“开源，让选择更多。”。面板标题叫“文字”，外观区却为空；没有字号/颜色/粗体；内容元素的 contenteditable 为 null。独立结果 `nativeText`、`fontControls=0`。同轮12页 h1 对照控件数为1，说明不是属性栏整体没加载。

定位：`packages/html-editor/src/commands.ts:4` 的 editable 白名单只包含语义标签和 data-ppte-kind=text；`workspace.ts:162–194` 却将其他非媒体对象显示成“文字”，真正编辑与格式控件仍被白名单排除。HTML-first 合同没有要求作者所有可编辑文本必须 h1/p 或产品类型标记；原型普通文本 div 是有效原生作者内容。

修复标准：提供明确、安全的文本对象识别/声明与选择逻辑，覆盖 div/span、嵌套行内样式等常见作者文本；不要把含多种对象的任意容器整块 contenteditable。确实不支持的结构要准确告知，而不是空面板。覆盖点击、输入、文字样式、撤销、保存重开；不得只给测试夹具加标记绕过问题。

证据：[文字属性](evidence/product-text.png)、[结果](evidence/followup.json)。

## R2 · P1：插入仍采用左上普通流，图片压住标题且无法按提示移动

操作：在同原型封面选择标题后插入文本或图片。文本落在(0,0)，侵入页眉；图片为320×240，同样落在(0,0)，与标题矩形(55,165,600,183.594)相交。点击图片后真实键盘 Alt+右键（ArrowRight），位置不变，UI反馈 `LAYOUT_UNSUPPORTED: 此对象使用普通文档流`。

定位：`commands.ts:296–342` insertionPoint/appendObject 选择参考对象父节点后，将新对象设为 relative、提高 z-index；图片避让只检查 h1–h6，所以 div 标题不在检测中。提高层级解决“图被标题挡住”却不能解决“图挡住标题”，也没有建立适用的调整操作。这是 N03 的遗漏分支，不可算全部关闭。

修复标准：根据实际内容容器和支持布局放置、提供可用调整能力，验证所有关键文字而不只标题标签；失败时撤销插入并准确说明。原生绝对定位画布可对新增对象使用适当定位，不能修改全部作者节点；流式画布要提供真实顺序/间距/对齐能力。不接受只通过内部 Commands 的回归。文本、图片、形状、表格均覆盖可见、可选、可调整、保存重开。

证据：[文本](evidence/inserted-text.png)、[图片](evidence/inserted-image.png)、[真实按键结果](evidence/followup.json)。

## R3 · P2：编辑画布退回全文滚动，当前页不适应可用空间

认可原型编辑时一页居中。最新产品编辑时清掉阅读视图，让所有页连续铺开；首屏同时显示第一页和第二页，当前页与画布边界不清晰。实测 iframe 可用宽940，而页面仍960；较小窗口继续裁切/滚动，属性面板展开也不按当前画布适应。

定位：`workspace.ts:362–367` scrollSlide 仅滚至页顶；`635–664` resize 在编辑分支调用 reading.clear，设置 iframe 变换/大小而非当前页工作台视图。它继承原始整稿页面流作为编辑视图，没有实现认可原型的单页画布行为。

修复标准：默认编辑以当前页居中适应并保留周围留白，页面栏控制当前页；如需超出适应比例的人工缩放，滚动仅为当前工作区服务。视图样式必须瞬态、隔离，不改作者持久布局、不固定响应式作者尺寸。切换模式、属性展开、窗口变化、翻页和保存后保真。

证据：[原型](evidence/prototype-edit.png)、[产品](evidence/product-text.png)、[几何记录](evidence/followup.json)。

## R4 · P2：控件只是统一边框，没有落实原型的信息层级

这不是要求截图逐像素相等，而是操作密度与信息组织有可解释退步：

- 顶部同时平铺保存、长文本下载、更多、放映、保存状态；放映缺主操作强调，保存信息又会新增整行改变画布位置。
- 字体直接显示 system-ui 文本框、颜色要求填写 rgb/CSS；字号加减、粗体、斜体、文字对齐各占一整行，常用样式挤占大部分右栏。
- 普通用户看到183.594px、原生流式布局、网格列、align-self相关参数等工程表达；几何精度和布局细节未按需要收敛。
- 页面列表每页常驻“上移/下移”两个大按钮，三页就接近占满半栏；底部也是长文字操作队列，明显比原型紧凑图标与分组更嘈杂。

定位：`workspace.ts` 内拼接的多层 CSS（约11–25行）、通用 button/field 工厂、refresh 的文字/布局区（194–312行）、thumbs 页操作构造、底栏；accessibility.ts 后续覆盖又引入多行工具区。应按组件与状态落实设计，不能只继续叠 CSS 补丁。

修复标准：落实 DESIGN.md 的文档栏/工具条/插入/对象属性/页面导航/底栏层级；颜色选择、合理精度、紧凑同组按钮、图标与可访问名称一致。页面排序保留键盘等效，但收于页面操作或选中上下文，避免每页按钮墙。保留重要保存错误可读性，同时不让常见状态反复改变整个工作区尺寸。以认可原型为基准并提交同内容对照，不能仅测 button 存在。

证据：[原型对照](COMPARE.html)、[新增文字属性](evidence/inserted-text.png)、[真实12页属性](evidence/twelve-text.png)。

## R5 · P2：390px窗口属性面板完全覆盖画布

实测选中标题后缩至390×844，属性面板覆盖整个中间工作区，用户调属性时看不到内容；顶部加模式/状态/长按钮、底栏多行，进一步占用高度。原型同宽下画布与属性区各自保留空间。

定位：`accessibility.ts` 的 max-width:580 将属性/页面栏 width:100%，但仍为top到bottom固定覆盖层；workspace resize 对小窗口将左右预留都设0，没有为属性区安排独立纵向空间。

修复标准：小屏使用可关闭、限定高度的属性区，并让当前页保持可见；导航与属性互斥。优先保留主操作，低频项收起。检查实际画布可见矩形，不只检查按钮在屏内、目标44px和抽屉互斥。

证据：[产品390](evidence/product-390.png)、[原型390](evidence/prototype-390.png)。

## R6 · P2：版本命名/容量调整退回浏览器 prompt 对话框

真实操作“更多→版本历史→保存命名版本”触发 `prompt('版本名称（最多 200 字）')`；列表管理按钮平铺，容量设置通过两个连续 prompt 加 confirm。普通产品输入流程没有统一样式、字段校验与上下文。

定位：`version-panel.ts:23–37`。保存权限选择器应保留系统原生交互；这里要修的是应用自己的命名/容量/恢复确认，不能借此重做或模拟浏览器安全授权。

修复标准：统一产品弹窗/行内命名，清晰字段、校验、取消、焦点返回和待保存标识；容量管理在一个可审阅面板完成。恢复/删除确认保留明确范围与后果。版本查看/恢复实际数据正确性继续沿用现有验证，不因更换UI损坏历史。

证据：[命名后列表](evidence/history-named.png)、[prompt类型与文案](evidence/followup.json)。
