## B1 · P1：Enter 换行后，标题降级成不可整体编辑的容器

真实操作：新稿首屏→编辑→双击标题→End→Enter→输入“新增一行”→点击页面设置退出输入→重新选标题。

浏览器在 h1 内生成 `<div>新增一行</div>`。之前 h1 contenteditable=true；刷新后 h1 contenteditable=false，字号控件数量0，面板变成“内容容器”，提示不能整体编辑。新行子div可单独编辑不等于原文本对象仍可用。最初的多行 fill 与后续真实 Enter 路径均复现，无内部 Commands 注入。

定位：`packages/html-editor/src/commands.ts:8–26` isTextObject/textObject 为避免误把混合容器当文本，拒绝块级子节点；`workspace.ts:146–149` 每次刷新按当前DOM重新决定编辑宿主。原生 contenteditable 的 Enter 产物因此被误认成作者混合容器。R1 纯div初始识别已经修好，但编辑后的对象身份不稳定。

修复标准：明确文本宿主与编辑事务规则，安全处理浏览器换行产物，保留内联格式和原作者结构；不能为了支持换行把任意混合容器整体开放编辑。覆盖 Enter/Shift+Enter、多行粘贴、选择格式、失焦重选、撤销重做和保存重开；确保原文本对象仍能连续编辑与整体设置样式。真实系统IME另验，不以合成输入充数。

证据：[真实键盘前后DOM](evidence/newline.json)、[失效面板](evidence/newline.png)、[可复验原稿](sample/source.html)。

## B2 · P2：普通 HTTPS 引用链接阻止生成，与阅读保留链接的方案有差距

新稿参考页包含两个普通 `<a href="https://…">`（GitHub项目、官方网站），安装版CLI增强返回 `ok:false, errors:[CONTENT_URL_REMOVED], rejected:2`，未生成成品；改为保留地址的纯文字才通过。这不是联网抓取图片或执行脚本，也不是此轮新引入的回归，而是实际制稿发现的现存能力/合同差距。

定位：`packages/html-document/src/content.ts:68–87` 把 href 纳入URL清理，只接受#锚点；对a/area不接纳普通HTTPS导航链接。已确认 UI 设计的阅读合同却要求保留原有链接与媒体使用，HTML原生参考链接应有明确方案。

修复标准：区分用户主动点击的安全导航与自动加载/执行资源，明确支持范围并与阅读合同一致。采用严格协议白名单、拒绝 javascript 等危险URL，保持原有恶意输入回归；不通过关闭清理器解决。离线打开不自动请求网络，点击外链时才按既定能力处理；不能静默删掉引用文字或假称链接保真通过。

证据：[首次CLI错误](evidence/enhance-first.json)、[包含原链接的源稿](sample/source-with-links.html)、[修正后结果](evidence/enhance-final.json)。
