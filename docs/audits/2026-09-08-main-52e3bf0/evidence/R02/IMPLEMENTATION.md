# R02 — 裁切事务与保存、离开流程

范围：FOLLOWUP.md 的 R02。R01 / R03 的完整合同、九页最终增强交付留给后续对应任务；PDF 维持 U04 未完成裁决。

## 实现

- `image-direct.ts` 暴露 `pending` / `cropping` 与统一 `resolvePending`。预览继续只在外层，正文和恢复草稿不包含未提交取景。初始框与当前框比较；无变化退出不建立图片框、不增加撤销记录。重复双击不重置当前裁切基准。
- 保存/下载先显示“完成裁切并继续 / 继续调整”；明确完成后同步提交一次事务，再继续原动作。确认按钮的用户手势可用于文件选择器和放映；不重复触发下载。
- 编辑工作区的动作、阅读/放映、页按钮/缩略图、对象选择、键盘选择/删除、图片替换共用出口：“应用并继续 / 放弃并继续 / 留在当前”。另一个图片的 pointerdown 不覆盖当前裁切。事务替换 DOM 后，选择按稳定 ID 重新获取节点。
- 顶栏“裁切中”独立于文件 dirty 和草稿状态；自动保存只读取已提交正文，成功后仍明确显示裁切在调整。beforeunload 同时检查未提交交互；Esc 明确取消预览。
- 保存失败不撤销已提交裁切，不修改原始图像字节；一次撤销恢复完整裁切前正文。替换和删除各自保留独立撤销事务。

## 仓库断言与证据

`tests/audit-followup-r02.test.ts` 通过构建后的 `node --test dist/tests/*.test.js` 执行，使用离线 Chrome headless 的真实指针、按钮、键盘、下载事件和本地落盘文件。旧断言未删改。

|合同|真实断言|
|---|---|
|手动保存/下载|确认前下载/写入次数为零；继续调整保留正文和 pending；完成后只下载一次，实际下载文件解析正文严格等于提交正文|
|预览对应结果|读取预览图片和提交后图片的真实边界框，x/y/width/height 误差 ≤1 CSS px；新浏览器进程重开后作者几何严格一致|
|模式/换页/选对象|阅读、放映、下一页、缩略图、文字对象、另一图片逐项执行留下/放弃/应用；模式可点击；应用结果下载落盘再重开正文一致|
|删除/替换|按钮删除、键盘 Delete、替换选择器均验证三出口；替换真实 PNG 后撤销替换，再验证裁切仍保留；一个裁切事务撤销恢复原正文|
|自动保存|先提交文字，再拖裁切预览，等待真实自动保存定时器；磁盘字节只含已提交正文，裁切 pending 仍为 true，状态同时说明已提交修改已保存和裁切仍在调整|
|失败|注入写入失败，实际原文件字节保持上次成功版本；裁切与原图保留，dirty=true；一次撤销恢复裁切前正文|
|Esc/无变化/关闭|Esc 后正文、撤销栈不变，pending=false；无变化完成/离开/下载不提示、不建事务；仅有预览时 beforeunload 事件被取消，Esc 后不再取消|

`verification/test.log` 是全量门禁原始日志；`screenshots/` 对照预览、保存确认与重开；`samples/` 是测试真实落盘 HTML（诊断夹具，**不是用户成稿**）。所有归档文件有 SHA256SUMS。

本地第 4 项仍需：在目标桌面授权当前 HTML → 裁切预览点保存并确认 → 检查实际原文件正文与摘要 → 已提交修改自动写回时继续裁切 → 取消裁切/保存失败/拒绝授权不丢修改 → 关闭浏览器并重开核对取景。录屏、实际文件摘要和正文与本目录自动化证据分开记录。下载不能替代该项。后续 DLV 应增强同一干净九页稿，本目录的诊断夹具不得混入成稿。
