## 必须修复的问题

### F01 · P1：直开 HTML 时，主要操作入口不可见

**复现：** 用本机 Chrome 直接打开交付 HTML，保持鼠标不在右下角。文稿内容可见，但没有可见的编辑、保存、放映入口。顶部栏是 `display:none`，唯一启动按钮“编辑 / 保存”是 `opacity:0`，只有意外悬停或键盘聚焦才显现。

**影响：** 单 HTML 是面向普通用户的唯一成品。用户不能自然发现如何进入放映或编辑；“干净放映”被错误扩大到首次阅读入口。方案第 3 节明确要求阅读时保留名称、状态、编辑和放映，不能靠说明用户去找隐形按钮完成交付。

**定位：** `packages/html-editor/src/index.ts:161–170`；初始化时只有 loopback adapter 路径主动显示顶栏。

**修复验收：** `file://` 首次打开即可看见清晰、紧凑的阅读顶栏；显示准确的未授权状态。只有进入放映后才采用闲置隐藏。Chrome/Safari 分别验证，不改成默认自动进入编辑。

证据：[直接打开截图](evidence/direct-file.png)、`result.json.directFileControls`。

### F02 · P1：连续新增两页，放映会同时显示两页

**复现：** 打开样稿的本地编辑入口，连续点击两次“添加页”，选择第 13 页后放映。第 13、14 页的 `data-ppte-slide` 都是空字符串；两个页面的计算样式都是 `display:block`，在观众视图重叠。

**原因：** `workspace.ts:259–263` 只为新页设置对象 ID，却将 slide identity 留空。`html-player/src/index.ts:35–38` 根据 `data-ppte-slide` 的值拼接显示选择器，空值会命中所有新增页。保存序列化可能规范化磁盘副本，但没有同步规范化正在编辑和放映的 DOM，因此不能用保存成功掩盖当前窗口的问题。

**修复验收：** 插入时即分配唯一、稳定且符合当前合同的页面身份。新增两页、撤销/重做、保存前后、重开后逐页放映，每次恰好显示当前一页，页面身份不漂移。为真实新增页面旅程补回归测试。

证据：[放映截图](evidence/two-new-pages-present.png)、`followup-result.json.twoNewPages`。

### F03 · P2：保护一个对象，会阻止添加无关的新页面

**复现：** 在样稿封面选中标题，点击“保护对象”，再点击“添加页”。页面仍为 12 页，界面报 `OBJECT_PROTECTED`。

**原因：** 新增页通过 `workspace.ts:258` 对整份文稿的父节点做 transaction；`commands.ts:30–31, 44–51` 将“包含受保护后代”的父节点整体视为不可修改。保护标题因此阻断本来不会改动标题的兄弟页插入。

**修复验收：** 使用有边界的插入命令和历史记录，使保护继续阻止对受保护对象的实际修改，同时允许增加无关页面。验证新增、撤销、重做及保存重开，受保护节点的 ID、内容、样式与保护状态不变。不要通过取消保护检查解决。

证据：[实际错误截图](evidence/locked-add-page.png)、`followup-result.json.lockedObjectAddPage`。

### F04 · P2：新建页面没有保持页面尺寸与设计上下文

**复现：** 在 16:9 样稿添加一页。原页面在编辑视口为 992×558；新页仅为 992×76.765625。新页只含无样式的 section 和标题，没有 `.slide`、容器尺寸或可工作的空白布局，标题还依赖外部容器单位。

**影响：** “添加页”得到一个短条，而非可继续制作的幻灯片。阅读、缩略图、放映的比例与其他页面不一致。它通过“节点数增加”的测试，并不等于完成设计方案要求的添加页体验。

**定位：** `packages/html-editor/src/workspace.ts:259–263`。

**修复验收：** 明确新增页的尺寸与样式来源，可选择继承当前页的安全设计上下文或提供明确的空白页面能力；保留 HTML/CSS 的原生表示，不重建 IR。验证基于 class、Grid/Flex 和容器单位的稿件，新增后仍可编辑、放映、打印并保持比例。

证据：[新增页截图](evidence/added-page.png)、`result.json.addPage`。

### F05 · P2：页面背景属性显示固定白色，无法反映实际设计

**复现：** 样稿封面是樱桃红，空选区属性面板的“背景”却显示 `#ffffff`；其他页面也是同一个固定值。

**定位：** `packages/html-editor/src/workspace.ts:137–138` 将初始字段值写死，没有读取当前页样式。

**修复验收：** 属性应反映当前页的实际背景。纯色、渐变、透明继承等情况有准确表达，未修改字段时不改变文稿；切换页面、撤销与重开后同步更新。不能把复杂背景伪装成白色。

证据：[红色封面与白色属性值](evidence/editor-initial.png)。

## 设计还原与范围说明

当前编辑器已解决旧版白底白字，也提供统一样式和 SVG 撤销/重做。但 H03 不能仅凭“没有 fieldset/select”就标为最终完成：方案要求的可折叠缩略图、画布缩放与控制柄、靠近选区的浮动格式栏尚未完整落地。当前固定两侧栏、底部格式栏、连续文档画布与原型存在明显差异，需要按方案逐项还原或取得明确的范围调整。

普通单元格点击还会被统一选为 table，无法通过常规点击直接进入文字格式上下文；本次将其作为交互补验项，未把内部 API 可选中 td 当成人工路径通过的证据。

这轮依据是新的 HTML-first 方案，不要求重新增加 PPTX、ODP、Keynote、旧 Recipe/IR 以及用户已删除的传统格式范围。图片/视频/表格“任意新插入”等更早愿景，不能在没有范围判断的情况下全部偷换成本轮强制需求，也不能把现有“替换资源”宣称为完整插入编辑能力。

## 证据边界

本机为 macOS 27.0（26A5425a）、Node v26.5.0、Chrome 152.0.7977.76。本轮使用实际安装的 Chrome **headless**，不是人工操作记录，也不是 Safari 证明。

本轮 Safari WebDriver 返回 `session not created`：连接/启动兼容 Safari 超时；记录在 [safari.json](evidence/safari.json)。这与仓库先前环境中“未启用远程自动化”的原因不同，不能照抄旧原因。现行测试将“拿到受阻证据”也算测试通过，所以 **53/53 不是 Safari 通过率**。

原生文件选择器仍主要是 API 合同模拟；真实中文输入法仍不能用 composition 合成事件替代。磁盘满和进程中断测试不等于物理断电试验。GitHub Actions 的远端运行、npm 正式发布、其他操作系统和低性能设备本次未验证。
