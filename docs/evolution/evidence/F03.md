# F03 — Native PPTX tables

Scope: semantic PPTX export of validated `core/table@2.0.0`. No document operations or editing semantics change. Tables stay ComponentElements; export reads a snapshot and never mutates it.

## Criterion evidence

All automated checks live in `tests/pptx-table-native.test.ts` and run through the repository's compiled `node --test` suite.

1. **Real editable table structure**: `real editable DrawingML cells preserve typed display, Unicode and source values` parses every XML/relationship part with Python's namespace-aware ElementTree and locates `p:graphicFrame/a:graphic/a:graphicData/a:tbl`. It compares every cell's text, rules out picture and text-shape substitutes, and compares retained typed source values and source revision. DrawingML tables reside inside slide XML, unlike separate chart parts; no fictitious standalone table relationship is introduced.
2. **Merges, dimensions, basic styles, numbers and downgrade reporting**: the rectangular-merge test checks all four merge positions, cell counts, row heights, column widths, exact frame offset/extent, fills, font size, bold/italic, alignment, and covered-cell source retention. The first test compares percent, fixed precision, boolean/null, Chinese/multiline content and long numeric strings. Header/caption/style tests check explicit property paths for unsupported formatting. Fractional-size tests verify rounding preserves the frame and multiple tables remain distinct.
3. **Truthful nativeTable**: forecast reports and compilation alone never set it. Only the actual table adapter's emitted XML passing structural/content/style verification earns the flag. Tests reject missing cells, changed numeric text, changed widths/heights/offsets, merge flags, fill and font changes, and label substitutes. Hidden/empty/legacy/custom tables, stale revisions, malformed source data and failed exports cannot claim it. The bundled capability report equals the returned report, including recomputed summary. JSON Schema requires adapter evidence for `nativeTable: true`, restricts it to semantic PPTX, and does not permit a fabricated client pass.

## Declared adapter subset

- Table rows/columns follow model order. Row/column sizes are relative weights fitted to the element frame, matching the existing SVG renderer's dimensional convention; defaults are 32/120 du. Rounding uses cumulative positions so extents remain exact in EMU.
- Rectangular merges emit `gridSpan`, `rowSpan`, `hMerge`, `vMerge` and continuation cells. Only the anchor displays content. `ppt/ppte/table-sources.json` retains the full model, including covered values, stable IDs, raw numeric types, display formats and fact/source references. It is source metadata, not Office-native numeric formulas or a roundtrip importer.
- Basic styles: six-digit hexadecimal fill/text colors; boolean bold/italic; cell-wide font size from 4/3 through 400 du; left/center/right alignment; top/middle/bottom vertical alignment. Cell style overrides table style. Borders use a fixed one-du solid gray rule. Unsupported keys or values are listed by property path and omitted.
- Text remains editable. Rich-text markup is currently flattened with an explicit downgrade; the full rich text remains in source metadata. No new run-level sizing or widget execution is introduced.
- Column labels become an editable header row. A nonempty caption becomes an editable first row spanning the table width; the additional row/layout change is reported. Unsupported rotation, flips and opacity are also reported, rather than silently claimed as preserved.
- Empty tables and v1 tables retain declared fallbacks and never claim nativeTable. Invalid source data, XML control characters, unrepresentable dimensions or more than 1000 columns fail export. Valid fallback metadata does not require fallback image bytes when the native adapter is used; invalid document resource references remain blocking.

## Validation boundaries and Q01 handoff

The report records `adapter: drawingml-table-v1`, `validation: passed`, per-capability structure/content/dimensions/styles, property degradations, and `clientValidation: unverified`. Font metrics and possible Office font substitution remain explicitly unverified. The runtime verifier checks this adapter's emitted XML subset; it is not a general OOXML parser or an Office conformance claim. Independent automated tests parse the package with ElementTree and validate the report with JSON Schema.

An additional local exploration using python-pptx 1.0.2 successfully recognized the table and 2×2 merge, changed a numeric cell, saved, reopened, and read the changed value and unchanged Chinese cell. This is library interoperability evidence only, not a target-client acceptance pass.

Q01 must select supported PowerPoint/Keynote/LibreOffice versions and record actual opening, cell editing, re-saving, reading order, merges, font substitution, layout, and screenshots. No GUI client or visual-fidelity pass is asserted by F03. Source metadata preservation after Office re-saving is also unverified.

Merge encoding follows [Microsoft's DrawingML table-cell implementation notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/de4562ba-7901-48df-9803-414ded131f2b). The adapter uses a native [DrawingML table](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.table?view=openxml-3.0.1) within its slide graphic frame.
