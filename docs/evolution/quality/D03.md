# D03 deck layout planning

## Implementation and use

`planDeckLayout(PresentationIR, DeckPlanningOptions)` is exported from
`packages/design-compiler/src/index.ts`. It returns ordinary compiled slide
proposals and a structured report; it never writes the source document. Existing
`compileSlide` and `compilePresentation` remain synchronous and compatible.
Materialize/initialize proposals through the existing Operation Engine path.

The planner enumerates only registered declarative recipes and eligible variants.
Required output contracts, purpose, slot capacity, constraints, minimum font size
and reading order precede scoring. Required targets with absent, unverified,
unsupported or disallowed mappings are rejected. These caller-declared target
contracts are selection inputs, not evidence of actual Office compatibility.
The planner does not execute controlled recipe handlers.

Default limits: six retained candidates per page, beam width eight, 4,096 candidate
evaluations, 10,000 state transitions and 10 seconds per measurement. Configured
limits are validated and capped. Scoring preserves semantic fit and applies a small
adjacent-repeat penalty, exempting consecutive metrics/chart/comparison pages.
Seeded canonical tie-breaking and sorted recipe/variant enumeration make the
result independent of registry insertion order. Exhaustion returns no partial
deck and records the stopping phase/page/counters.

For browser verification, import `createBrowserLayoutMeasurer` from
`packages/design-compiler/src/browser-measurement.ts`. Supply a dedicated,
caller-owned Chromium Page, a document rendering template with the intended
canvas/theme, data-URI font/resource bytes and renderer build digest; pass the
returned callback as `measure`. Calls using the same page must be serialized.
The adapter snapshots the template, uses the production HTML renderer, loads
explicit FontFace bytes, awaits fonts and image decoding, measures actual text
Range rectangles, checks Chromium's actual glyph font sources, and captures a
screenshot. It does not fit/shrink text. Missing glyph fallback, broken fonts,
resource failure, unsupported browser instrumentation and timeouts fail the run.

Reference text advances remain a conservative preflight without a browser.
Successful real-font evidence supersedes a reference overflow; unverified
measurement cannot bypass that rejection. No browser yields `visualStatus:
unverified`, never visual pass. Measurement callbacks receive cloned drafts;
stale, incomplete or mutated-draft evidence is rejected.

Reports include every evaluated candidate, rejection/selection reasons, seed,
limits/counters, stop codes, measurement provenance and connected keepTogether
block groups for explicit split review. Splits are proposals, not executable
capacity guarantees; a single oversized group needs a different recipe or a
content decision. No block is deleted or rewritten. A report's identity binds
IR, recipe package contents, theme/document, canvas, seed, compiler/font settings,
target contracts, caller delivery identity and actual measurement evidence.
`isDeckLayoutReportCurrent` compares that identity with a newly planned report;
it is freshness checking, not authentication or export certification. Include
history/runtime/export configuration in `deliveryIdentity` when applicable.

## Criterion evidence

All six cases are in `tests/deck-layout-planning.test.ts`, compiled and executed by
`node --test dist/tests/*.test.js` through `pnpm test`.

1. Hard constraints before aesthetics / bounded candidates / deterministic seed:
   the hard-constraint test makes an impossible recipe preferred, tests eligible
   variants, reversed registry ordering, stable drafts, retained content, deck
   rhythm and search bounds. The output-contract test covers missing,
   unsupported, unverified and rasterized mappings against a native requirement.
2. Actual font measurement and browser review / no browser unverified:
   the browser test covers normal and exact single-line boundary screenshots,
   a real-font fit rejected by reference advances, actual overflow, invalid font
   bytes, unpinned fonts, missing-glyph fallback and invalid image bytes. The
   no-browser test checks explicit unverified status. Stale measurement, thrown
   errors and timeout are negative cases. The fixture font is original, pinned,
   synthetic ASCII test data, not a claim of visual design quality.
3. Structured selection / split / budget reports:
   report tests inspect reasons, identity invalidation, indivisible linked block
   groups and required explicit split review. Candidate/search limits and invalid
   budgets are tested, and exhaustion returns zero drafts. The browser test also
   verifies that a mutated measurement draft cannot become accepted evidence.

## Verification artifacts

Final verification counts and environment are recorded below after execution.
`d03-blackbox-start.json` and `d03-blackbox-final.json` retain the complete gate
reports. `d03-measurements.json` retains 30 actual browser module samples for each
of 12, 30 and 100 pages, with separate p50/p95 by size, raw timings, work counters,

screenshots; it does not claim application startup or input latency. Repeated
samples use the same browser session, with a freshly mounted page for every
candidate. Normal and boundary screenshots are retained next to the report;
tests also write all screenshots to ignored `artifacts/d03/`.

## Remaining scope

This is a bounded initial beam heuristic, not a proof of global aesthetic
optimality. D04's real style/role corpus and D07's human visual gate remain
separate. Synthetic ASCII capacity evidence does not certify all fonts/languages.
Safari, low-performance physical devices and Office clients remain unverified.
The browser adapter currently requires Chromium CDP to detect glyph fallback.
Per-measurement timeout prevents late results from entering the report; the
caller owns disposal of its browser page. Existing declarative baseline
constraints remain explicitly unsupported as established by D02.
