## Implementation and criterion evidence

All six tests are in `tests/table-editing-journey.test.ts`, executed by the normal
`node --test dist/tests/*.test.js` framework.

1. **Host structure/cells; Portable values/styles and explicit permissions.**
   The fourth test exercises viewer, quick-fix, light-edit and full-portable,
   rejects structural and generic-props bypasses, verifies locks and presentation
   mode, HTML/SVG fill rendering, and checkpoint history. The browser journey test drives
   the actual built Host and generated `file://` quick-fix Portable: direct stage
   cell selection, typed boolean editing, fill, row/column insert/delete/move/
   resize, merge/split, and save/reopen/undo/redo. Portable shows its narrower
   permissions and has no structural controls. Existing full-portable arbitrary
   transactions continue for other objects; tables use typed value/style edits.
2. **TSV/space/ragged/merged boundaries, navigation and undo.**
   The first test checks empty strings/cells, retained spaces, CRLF, Chinese and
   long digit strings, ragged rows and overflow, single-anchor merged edits and
   rejected multi-cell paste through merges, and a single reversible transaction.
   The second checks reverse rectangular selection, tab/back-tab and arrow edges,
   including skipping covered cells. The browser journey drives actual clipboard events,
   Shift+Arrow range selection, Core keyboard undo, rejected paste with unchanged
   revision, and both persisted editing journeys. Locked-cell commit failures preserve the
   input and revision in both real browser surfaces; presentation hides the panel.
3. **Unaffected identity and fact/source stability.**
   The third test commits each structural proposal through Core, asserts the
   untouched complete cell record and fact/source lookup IDs, and checks exact
   undo/redo revisions. Deleting a referenced row is rejected with a concrete
   affected-cell list before any commit. Empty tables can start with axis
   insertion. The browser journey also checks untouched cells across row and
   column structure edits. Merges retain covered values; the panel explains that
   the top-left cell is displayed.

Every write is an Operation Engine transaction. Selection, clipboard parsing,
input and error state are transient. No new dependencies or format/profile
versions are introduced.

## Limits

- A21 target-user sessions with the product owner and two users were not run;
  this evidence covers the automated table task and accessibility journey only.
- Physical IME, Safari and low-performance physical devices remain unverified.
- Clipboard input is rectangular TSV; spaces and long numeric strings stay text.
  Quoted spreadsheet/CSV parsing and automatic table expansion are not provided.
- Structure crossing an existing merge must be split first. Referenced deletion
  is rejected by this UI with its impact list; an explicit reviewed semantic
  operation can be performed through the existing Host/Agent review workflow.
- The editor provides basic fill styling. Native Office table export/client
  validation belongs to F03 and is not claimed here.
- Cell value/TSV fields use explicit Apply buttons; only applied input is saved.

## Gate fix: retain table keyboard focus

Fix-round baseline: `1b67b4088d7e204368bbabcea4e6f4636ce1f353`.
The initial full suite passed 326/326, but the focused original F02 journey
reproduced the intermittent failure: after applying fill, keyboard Undo left
`{fill: '#ffeeaa'}` instead of restoring the absent style. The complete failure
is retained in `f02-fix-reproduction.tap`.

The shared table renderer replaces its controls on each render. Host status and
recovery updates can therefore detach the focused cell between focus and the
Undo keystroke. The renderer now restores the corresponding control only when
focus was inside the same table. It also retains draft text selection and falls
back to the selected cell when a structural edit removes the focused cell.
Outside focus is not moved. All document changes still use Core transactions.

The new deterministic browser test rebuilds a focused table panel, checks that
history shortcuts still reach its cell, navigates to the next cell, and checks
an unfinished draft and selection across another render. It also checks outside
focus. Running this test against the pre-fix source fails with lost focus,
shortcut delivery, navigation and text selection (`f02-fix-regression-before.tap`).
The fixed focused suite passes all six tests, including the unchanged real Host
and Portable keyboard Undo assertion. Final gate results are recorded in
`f02-fix-verification.json`.
