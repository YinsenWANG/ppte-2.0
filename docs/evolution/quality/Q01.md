# Q01 client and delivery acceptance

Q01 is **partial**, and release acceptance remains **unverified**. This change implements an evidence contract, not completed manual acceptance. D07 is still partial. Safari and LibreOffice are installed on this machine, but application availability is not evidence of executing the required journey. No actual-client or human-panel result is fabricated.

## Criteria and executable evidence

1. `tests/client-acceptance.test.ts` requires real Safari and Chrome targets and rejects Playwright WebKit as Safari evidence. `client-matrix.json` pins Host, single HTML, and offline-directory browser entries. These are required verification targets, not verified support claims. PowerPoint, Keynote, Firefox and Edge are explicitly not declared.
2. The same test file independently removes each Office requirement: open, edit, resave, native text/shape/image/chart/table, text order, and visual review. Every omission blocks acceptance. Package inspection is rejected as client evidence; resaving requires a separate changed file, and visual evidence requires a screenshot. Existing PPTX adapter structure checks remain unchanged and do not imply Office compatibility.
3. The test file exercises all ten ArtifactIdentity components, stale matrix digests, forged identities, missing or corrupt retained bytes, duplicate/unknown observations, and all non-pass statuses. Missing file verification defaults to rejection. The blackbox `review-patch:Q01-client-evidence` gate builds a real Portable artifact and checks that empty evidence yields zero client passes and blocked acceptance.

The six new unit tests include synthetic positive records solely to exercise the validator. Their mock image/PPTX bytes are not real client artifacts and are never written to the published matrix as observations.

## Consuming actual-client evidence

Import `evaluateClientAcceptance` from the capability package. Supply the versioned matrix, a `ClientSubmission`, the current deliverable's **recomputed** ArtifactIdentity, and a callback that reads each evidence path and verifies its SHA-256. The default callback rejects everything. Retain original input bytes, screenshots/trace, and edited/resaved Office bytes; include application/version, OS/device, executor/time, scenario, operations, expected/actual, document revision and history digest for every check. Use a separate submission for each actual delivery identity. A caller must establish the input-to-deliverable binding; this validator cannot attest that a human really performed an action or authenticate the reporter. Hashes are not signatures.

A passing client evidence contract alone does not close Q01. A19 installed-package and Skill journeys and the D07 benchmark at M3, including the product owner and two target users, are independent release requirements. No M3 table task may be deferred. The matrix references the existing executable authoring, table, media, installed-package and Skill journeys. Their automated results cannot replace the human panel.
