# F06 — 现场工具与可恢复双屏

## Contract and implementation

The existing window is the audience surface. A user-opened same-origin `about:blank`
presenter window shows speaker/handout notes, page controls, the timer and a static
next-slide preview. Both Host and Portable mount the same DOM adapter. All tools
are ephemeral; navigation uses the existing presentation controller and never
submits document operations. Leaving presentation removes listeners, intervals,
visual overlays and the presenter window; a new presentation starts fresh.

Blackout covers the audience slide without changing its animation step. The
pointer overlay follows audience-surface pointer movement. Timer start/pause/reset
uses a monotonic clock. Page entry is one-based in the UI, bounded to actual slide
indices. Preview frames are sandboxed without scripts or same-origin access;
preview assets use data URLs so Host Blob restrictions cannot break them.

The independently bundled presenter entry executes in the child realm, ensuring
`postMessage` has the real child `event.source`. The v1 transport checks the
window object, exact origin, random session and token, integer sequence numbers,
and ACK bounds. It uses stop-and-wait, retries dropped data/ACKs, applies each
command once, rejects sequence gaps and retains up to 64 queued commands (with
visible backpressure). Complete state snapshots coalesce to the latest queued
snapshot. No out-of-order command is applied speculatively. Authenticated silence
for 3.5 seconds is shown as disconnected; retransmission continues. Window close
is detected, and the reconnect button opens a new window with fresh credentials.

`file://` and opaque origins deliberately keep single-screen tools and explain
that dual screen is unavailable. Denied popups also keep all single-screen tools.
Portable removes its serialized payload script from the audience DOM during
presentation and restores it on exit; its notes element is empty in presentation.
Host unmounts its notes editor. Notes are sent only in presenter-bound snapshots.
This is DOM isolation during projection, not a claim that notes are secret from
someone who possesses or can inspect the original presentation file.

## Per-criterion executable evidence

All cases are in `tests/presenter-tools.test.ts`, compiled and run by the existing
`node --test dist/tests/*.test.js` framework.

1. **Index / blackout / laser / timer / next page / transient state:** monotonic
   timer test plus the shared real-browser journey in generated file Portable,
   HTTP Portable and HTTP Host. The browser checks index entry, navigation,
   blackout visibility and unchanged animation step, pointer visibility, timer
   controls, actual preview iframe content and decoded preview images, read-only
   audience text, unchanged revision/history and successful exit.
2. **Recoverable authenticated dual screen:** protocol tests inject invalid
   version/session/token/source/origin/sequence/ACK, duplicate and out-of-order
   messages, lost data and ACKs, rapid queued commands, obsolete sessions, queue
   saturation and disposal. Real HTTP Host/Portable tests open the actual child,
   exchange commands and ACKs, reject wrong-source/wrong-token/stale-session
   messages, drop child traffic until the disconnect indicator appears, restore
   delivery, close the popup and reconnect with the current state. Closing the audience
   closes its presenter endpoint; reopening the saved Portable or recovered Host
   deck starts a fresh single-screen session with reset tools.
3. **Notes isolation and fallback:** browser checks that synthetic speaker-note
   markers are absent from the entire audience body text (including scripts),
   while present and updated in the presenter window. File-origin and denied
   popup cases retain working tools, leave safely and restore Portable's payload
   and editing notes. Screenshots preserve the observed two-window UI.

## Scope and remaining risks

- Automated Chromium desktop journeys cover the F06 portions of A06/A16/A21.
  Product-owner and two-target-user manual A21 journeys remain **unverified**.
- Physical dual-monitor placement, real Safari, low-performance devices and
  operating-system popup policies remain **unverified**. Windows may be moved to
  a second display by the user; the app does not claim automatic monitor control.
- Opaque/file-origin dual screen is intentionally unsupported. Same-origin
  HTTP(S) with popup permission supports dual screen; restrictive CSP or missing
  secure randomness falls back or reports a disconnected presenter.
- Laser movement is driven by the audience surface. Video next-slide previews
  are static; this work does not change F04 playback guarantees.
- The protocol is ephemeral window control, not multi-user collaboration, durable
  synchronization, CRDT, or a widget execution mechanism.
