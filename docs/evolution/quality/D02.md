# D02 — recipe execution contract (A14 subset)

D02 implements the bounded **declarative** recipe compiler. Drafts and transaction
proposals remain the only outputs; document writes still use the Operation Engine.
Compiler identity is `design-compiler-1.1.0`. No font shrinking or content truncation
is used to make a recipe fit.

## Declaration → validation → execution → tests

All tests below are in `tests/recipe-execution-contract.test.ts` and run through
`node --test dist/tests/*.test.js`.

| Declaration | Execution / explicit rejection | Test name fragment |
| --- | --- | --- |
| variants | Equality predicates on density, purpose and visualStrategy only. One eligible variant applies; overlapping predicates require explicit eligible `variantId`. Unknown predicates, duplicate IDs, zone renaming and invalid geometry reject. | variants apply equality predicates |
| accepts, required, minCount, maxCount, maxChars | Bounded backtracking reserves restricted slots and respects lower/upper bounds. required cannot be defeated by minCount=0. maxChars recursively counts arrays and objects as a conservative prefilter. | matching reserves restricted slots |
| keepTogetherWith | Linked blocks must fit the same slot; missing references and incompatible capacity reject. Connected sets produce flat logical groups. | keepTogetherWith is a capacity relation |
| keep-together | Slot members produce merged flat groups on the one compiled slide; no nested coordinates or automatic splitting. Groups survive materialization. | keepTogetherWith is a capacity relation |
| padding | Sequential inset of the named container; nonpositive final geometry rejects. | constraints reject impossible final geometry |
| min-size / max-size | Resize slot containers, then verify final postconditions after all other constraints; conflicting limits reject. | constraints reject impossible final geometry |
| aspect-ratio | Fit the normalized container to the positive declared ratio around its center; later contradictory transforms reject. | constraints reject impossible final geometry |
| safe-area | Fit slot containers to the canvas safe area; contradictory constraints reject. | constraints reject impossible final geometry |
| avoid-region | Deterministic displacement, followed by final intersection and bounds checks; infeasible avoidance rejects. | constraints reject impossible final geometry |
| align / stack / grid / gap | Deterministic normalized container transforms, with final feasibility and postcondition checks. Grid uses at most the number of available containers. | alignment, stack, gap and grid execute |
| baseline | Explicit `RECIPE_UNSUPPORTED` diagnostic inside the compiler's infeasibility result. Real text baselines require measured metrics; no fake bottom-edge alignment. | constraints reject impossible final geometry |
| max-elements | Counts all emitted elements, including optional artwork. | all quality rules execute |
| min-font-size | Checks resolved theme/preset font size; never modifies it. | all quality rules execute |
| max-overflow | Checks deterministic reference text measurement; multiple declarations use the strictest allowance. | all quality rules execute |
| required-reading-order | Checks completeness and uniqueness of generated content reading order; materialization also rejects incomplete reading order. | all quality rules execute |
| repeat | New nested syntax `{version:"1.0",maxCount,columns,gapX,gapY}`; bounded positive integer counts ≤128 and normalized gaps. Unknown versions reject. Parameters determine layout; no fixed three-column override for this syntax. | versioned repeat uses declared columns |
| limits | IR permits 64 blocks; matcher caps direct inputs at 128, search at 100000 states, registry at 128 entries. Budget exhaustion is a separate `RECIPE_SEARCH_LIMIT`, never evidence of mathematical infeasibility. | search and registry have deterministic hard budgets |

Zones describe normalized **slot containers**; repeated cells subdivide their
container. Existing recipes without `repeat` retain their legacy distribution.
Padding is an ordered inset operation; the other geometric constraints are checked
as final postconditions. Unsupported execution syntax is rejected by runtime
validation rather than treated as an extension or executable code.

A failed assignment returns no partial drafts. Invalid draft materialization is
blocked, including initialization/regeneration paths that call materialization.
Recipe Studio keeps all failed boundary cases and diagnostics in its report, with
no fabricated preview. The existing Host browser test exercises the 17-case report.

## Identity and compatibility

Element IDs derive injectively from content keys, including punctuation and UTF-16
code units, not repeat position. Reordering content preserves IDs. Array content is
serialized rather than discarded. Registry reads/writes snapshot declarative data.
Fixed input, recipe, compiler, seed, theme and metric identity produce equal drafts.

`tests/fixtures/evolution/d02-legacy-compile.json` was captured from the task-start
compiled implementation (commit `2237cd529dfc5b08352f9a54fae995336cafae5e`) before
compiler edits were built. Its cover output remains identical except for the new
compiler version. Built-ins whose old grid/gap/baseline declarations were incorrect
now carry recipe version 1.1.0. Old explicit references to those 1.0.0 recipes must
supply their original registered spec or select the new version; there is no silent
version substitution. The timeline no longer declares an unimplemented baseline.

The pre-existing `registerControlled({trusted:true, compile})` API remains an
explicit host-code trust boundary, with its existing compatibility test unchanged.
It is not serialized declarative syntax and is not a sandbox or a promise to bound
arbitrary trusted JavaScript. D02's search/content-placement guarantees apply to
declarative recipes; supplied controlled handlers retain responsibility for their
custom semantic transformation.

## Verification and limits

The task-start suite passed 233 tests. Final command outcomes and report digests
are recorded in `d02-verification.json`; blackbox start/final JSON are retained next
to it. A full-suite run exposed Recipe Studio attempting to materialize failed
samples; that integration was fixed without weakening the existing assertion.

This completes D02's execution/capacity contract, not the whole A14/G2 release gate.
Reference text metrics are deterministic estimates, not browser/font-ready visual
proof. Font-ready screenshots, style-role coverage, physical devices and Office
client validation remain D03/D04/D07 work. Baseline stays explicitly unsupported.
No automatic split, arbitrary widget execution, CRDT or realtime collaboration was
introduced.
