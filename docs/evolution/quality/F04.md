## Use and compatibility

Host and editable Portable have a **导入视频** file input. Preparation decodes before a single Engine transaction adds asset and component. Host stores prepared bytes in recovery storage before committing. Imported videos without a selected poster have a labeled static placeholder in exported formats. A caller can supply a verified image poster through `prepareVideo` / `planVideo`; poster IDs and metadata survive persistence.

`planVideo(..., migrateSource)` upgrades an existing v1 component only when the caller explicitly supplies both the matching source string and prepared local file bytes. It does not fetch paths or URLs. Unresolved legacy files retain their old fallback. Grouped v1 migration requires an explicit ungroup first; there is no hidden group restructuring. Existing v1 capability downgrade assertions remain intact.

The Node adapter `deliverMediaDirectory(target, document, options)` is exported from `packages/node-runtime/src/delivery.ts`. The target must not exist. It returns the entry path and verification contract only after all written files compare equal to the built bytes. Files are `index.html`, `manifest.json`, `template.html`, and deduplicated `media/<sha256>.bin` resources. MIME comes from the validated Asset metadata, not the `.bin` suffix.

To open this directory, serve it using a local static HTTP server bound to loopback and visit its `index.html`. This is offline with respect to external networks, but it requires the local server. The directory is **not** a double-click/file:// delivery. The entry explains this restriction before attempting fetch. It reconstructs the self-contained runtime only after verifying all resources; it does not stream arbitrary relative media or execute unverified template code.

Packing checks CAS and the complete Portable artifact; opening checks files against the entry's pinned manifest and complete reconstructed HTML. These hashes are integrity checks, not publisher authentication. Changing both the trusted entry and all its hashes is outside that integrity promise. No source project is modified by either delivery path. A process crash can leave an incomplete newly created directory; no result has then declared successful delivery, and opening cannot execute an incompletely verified runtime.

## Capacity and scope

No standard attachment budget was increased. Base64 expansion and the full runtime count toward 20 MiB. The directory reduces on-disk base64 duplication but reconstructs the full HTML and uses Blob media in memory; it is not a streaming or low-memory solution. The 128 MiB import limit is a conservative hard guard, not a promise that a 128 MiB asset meets the 20 MiB attachment target or has measured smooth playback on every device.

Raw observations, current build identity and gate results are recorded alongside this report after verification. Startup labels are first navigation in a fresh browser context versus repeated navigation; they do not claim to evict the operating-system disk cache. URL/player counts measure explicit controller-owned resource retention, not precise garbage collection or total process memory.

Unverified: real Safari, low-performance physical devices, physical audio output, arbitrary codec combinations, native PowerPoint/Keynote/LibreOffice video playback. The fixtures are silent; PDF/PPTX explicitly retain static posters and do not claim embedded media or client fidelity. Existing guarded editing and persistence behavior remains covered by the full repository suite.
