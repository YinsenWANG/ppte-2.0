# P01 — partial browser measurement protocol

P01 remains **partial**, and A20/G4 remain **unverified**. The checked-in evidence measures the real offline `full-portable` file entry on this machine. It does not certify the Host, Cherry material, 50 MiB resource corpus, or another physical device.

Run `pnpm build`, then `node scripts/perf-browser.mjs /tmp/new-p01-report.json`. The destination must not exist; frozen evidence is not replaced by default. Run without competing test/build loads. The script verifies resource and document hashes before launching Chromium. Compare trials only with identical protocol, document/resource/font hashes, browser binary/version, CPU/OS/memory, viewport, locale and entry. A different machine gets a separate report, never pooled samples. CPU throttling is not a replacement for lower-performance hardware.

The original Node benchmarks now identify Session construction, slide HTML generation, hit testing, transaction commits, journal creation/append, history undo/redo, checkpoint writing, and Portable artifact building. Their existing assertions and budgets are retained; none claims browser readiness or paint.

`tests/fixtures/evolution/performance-manifest.json` freezes `p01-candidate-v1` before sampling: cold/warm startup 2000 ms p95, page switch 100 ms p95, input/drag feedback 50 ms p95, continuous-drag pause 100 ms maximum. These remain candidate targets. There is no new calibrated release budget and no automatic product pass. Engine text-commit duration and whole-gesture duration must not be compared to single-input feedback targets.

All three deterministic synthetic tiers contain 30 objects per page plus a video; the 100-page tier also includes charts. They have pinned embedded Noto Sans SC subset bytes, a tiny PNG, and a real VP9 clip. The manifest explicitly records that the 12-page tier is not Cherry and the 30-page tier is not 50 MiB. Generated document hashes and built HTML hashes are separate. The report records source hashes and whether the measurement checkout was dirty, as well as the runtime build manifest.

Each tier retains 20 fresh-process startup samples and 20 same-context reload samples; OS disk caches are not cleared. Readiness awaits the API, font load, decoded images, video metadata, two animation frames and selection. Each interaction has 30 samples: Engine text commit and paint, actual page change, undo, redo, checkpoint/download initiation, Playwright pointer gesture and paint, and muted media play/pause plus leave/return. Continuous rAF intervals during drag are stored separately. The save sample excludes physical disk flush; reopened checkpoint semantics are verified separately. Exact undo and actual drag revision changes are required. p50/p95 use linear interpolation at `(n-1)*p`; raw values, count and maximum are retained without replacing the tail with an average.

`tests/performance-browser.test.ts` maps tests to each criterion:

- Criterion 1: exact Node names, deterministic valid tier fixtures, real Portable builds and a live offline browser edit/paint/navigation/undo journey. Original Cherry/50 MiB Host sampling remains missing.
- Criterion 2: pinned resource tamper rejection, device/browser provenance, loaded font, complete separate raw sample distributions and browser correctness. Physical low-performance/Safari/IME coverage remains missing.
- Criterion 3: undersampling/nonfinite rejection, exact percentile recomputation, immutable candidate values, budget-inflation rejection and rejection of a forged acceptance pass. Actual whole-product calibration remains missing.

The blackbox case `P01-performance-evidence` independently recalculates p95 and checks the unverified disposition. A green evidence-contract test does **not** mean A20 passed.

Outstanding work includes the original Cherry corpus, the 30-page 50 MiB actual-resource Host entry, physical lower-performance hardware and Safari, real IME/pointer feedback, unrelated DOM/focus/playing-media stability, and at least 20 memory/disposal loops. Font fallback outside the pinned subset is also unverified. Complete those measurements before freezing a calibrated product budget or marking P01 done.
