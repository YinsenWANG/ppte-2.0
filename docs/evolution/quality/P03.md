# P03 — Incremental indexes and trusted cancellable jobs

Core now retains per-slide index contributions and reconciles only keys belonging to changed slides. Changes are determined from committed snapshots, never a caller-mutated preview diff. Reconciliation follows document storage order, including duplicate identifiers across slides. Slide-storage reorder and partial-update failures use the full builder. External index readers receive defensive Map/Set copies. Commit, undo and redo share the same updater; explicit index recovery changes no document, revision or history.

`BackgroundJobs` provides a bounded, latest-input-wins lane for a closed `canonical-hash` operation. Each request has a pool-scoped unique job ID, base revision, canonical input digest and frozen private input. It supports AbortSignal, explicit cancellation, timeout (including time spent queued), revision/input invalidation, executor errors, backpressure and idempotent disposal. Aborted physical work retains its slot until the trusted executor settles. Returned envelopes are validated; consumption checks freshness again, rejects forgery and is single-use. Controller-owned queues invalidate on Engine commits/undo/redo and dispose when the controller closes. There is no document write or alternate commit path in the queue.

Worker executors are trusted application code, not a script sandbox. The operation vocabulary accepts no scripts, module URLs or widgets. **No production operation is migrated to a Worker.** The queue defaults to native execution, is created only on request and does not change synchronous canonical revision or checkpoint semantics.

## Evidence by criterion

All cases are in `tests/background-job-contract.test.ts`, compiled and run by the existing `node --test dist/tests/*.test.js` test command.

1. Full-index equality: Engine edits/undo/redo/rejected commits; semantic keys, references, roles, images, groups, slide duplication/deletion; 80 deterministic mutation steps; failure injected after partial reconciliation; defensive reads; non-slide edits; repeated identifiers and storage reorder; pinned 12/30/100-page fixtures updating exactly one slide.
2. Trusted scheduling: frozen input, unique identity, exact jobId/baseRevision/inputDigest/hash verification, pre-abort/running/queued cancellation, running and queued timeouts, bounded physical concurrency and queue, executor failure, close and resource cleanup. The profiling test executes native and real Chromium Worker paths and validates retained fixture identities and sample summaries.
3. Stale rejection: reverse completion order, changed revision/input, late consumption, cancelled delivered results, closed controller and forged proposals; stale Engine transactions remain rejected. Native versus Worker total-cost evidence is retained separately from compute-only measurements. Unsupported executable operation kinds are rejected.

## Cost experiment and decision

Run `pnpm build` then `node scripts/p03-job-benchmark.mjs` to reproduce `p03-job-costs.json`. The test runs the experiment without rewriting evidence. It uses the P01 pinned 12/30/100-page synthetic fixtures, a real Chromium Worker containing only the canonical hash implementation, five warm-up iterations and 30 raw samples per metric. Execution order alternates. Both total-cost paths use the actual BackgroundJobs queue, including private input copying/freezing, digest binding, dispatch, output validation and consumption. Worker startup is measured separately; warm Worker totals include structured cloning and roundtrip. Source bundle digests, fixture digests, CPU, OS and browser version identify the measurement.

Retained p95 measurements in milliseconds:

| Pages | Hash compute | Full index build | Native job total | Warm Worker job total | Cold Worker total |
| --- | ---: | ---: | ---: | ---: | ---: |
| 12 | 1.7 | 0.3 | 3.5 | 7.1 | 19.1 |
| 30 | 3.5 | 0.3 | 8.2 | 10.1 | 19.5 |
| 100 | 11.6 | 1.3 | 26.6 | 33.1 | 53.3 |

The retained measurements show Worker p95 total cost above native total cost for every corpus. Full index construction remains inexpensive in these fixtures. Hashing a large snapshot is measurable, but dispatch does not eliminate the main-thread input binding cost and increases total cost. Therefore the measured jobs remain native; no compression/measurement job is invented or migrated without a demonstrated hotspot. File-format checkpoint writing is synchronous and uses stored ZIP entries; its I/O and durability boundary remains intact.

This is a computation/scheduling comparison on synthetic corpora, not a claim that browser interaction, checkpoint I/O or all A20 budgets pass. Native computation cannot be preempted mid-call; freshness and deadline checks suppress its result after return. A future Worker executor must terminate/release work and settle active promises on disposal. A20's physical lower-performance device, real Safari, physical IME and other P01 gaps remain unverified.

Verification details and baseline comparison are recorded in `p03-verification.json`. The initial full-suite baseline had a failure in the existing F02 narrow Portable table-focus browser assertion; no assertion was weakened or removed.
