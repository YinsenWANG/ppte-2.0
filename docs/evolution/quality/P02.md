# P02 — Incremental surfaces and browser resource ownership

The Host and offline Portable use `IncrementalRenderCache` for page and object HTML. Snapshot-derived dirty sets include semantic changes and referenced resource changes; unrelated resource IDs do not invalidate a page. Canvas/theme changes conservatively invalidate the cache. Entries for deleted pages/objects are pruned. The DOM reconciler skips unchanged keyed subtrees while preserving active text and media; explicit draft discard or transform rollback can force reconciliation.

Both interactive canvases mount the current slide and immediate neighbours. Host keeps its existing single active `.ppte-rendered-slide` contract and mounts neighbours in an inert hidden sibling. Portable reconciles the ordered window in place. Search, navigation, page labels and order still use the semantic document. Print creates an independent full-document surface, hides the interactive shell and removes the temporary surface after print. Full HTML/SVG/export rendering remains independent of the interactive cache/window.

`BrowserResourceCache` owns digest/MIME-keyed Blob URLs and digest/family/weight/style-keyed FontFace instances. IDs with identical bytes share resources. Changed/removed metadata releases obsolete resources; dispose releases all owned URLs and faces. Failed font loads evict their entries for retry on the next resource sync; callbacks from released attempts cannot remove a newer attempt or reattach a released face. Media retains its existing digest cache and playback-position owner. Caches do not own or delete checkpoint/undo resource bytes.

Thumbnails have a separate read-only, static-media render cache. Portable updates only changed previews; Host uses a memoized thumbnail surface to avoid React rewriting unchanged HTML. Deleted page entries are removed. Cached HTML is derived data and never a document write path.

## Criterion evidence

All new tests are in `tests/incremental-rendering.test.ts` and execute through the repository's `node --test dist/tests/*.test.js` framework:

1. Dirty page/object sets are compared with full renderer output after edits, reorder, deletion, canvas/theme and resource changes. A Chromium DOM test retains the composing text node, focus, neighbour page, video node and currentTime, observes zero unrelated mutations, and verifies forced geometry rollback. Offline Portable and mounted Host tests perform real Engine text edits and verify neighbour/thumbnail identity.
2. Chromium resource-owner tests verify identical digests/aliases reuse URLs and font loads, changed bytes replace URLs, failed loads retry, removed/disposed resources release exactly once, and a late rejection cannot resurrect a face. The Host fixture also supplies real pinned embedded font/image bytes. Existing F04 media journeys and E03 text journeys remain unchanged.
3. A 100-page fixture verifies the bounded window, local thumbnail invalidation and exact full-export page order. Live Portable and Host navigate to the middle of a 12-page deck, verify mounted neighbours and all 12 printed pages, and verify print cleanup. Portable additionally checks exact undo revision.

## Scope and remaining limits

This closes the P02 implementation criteria, not all of A18/A20. P03 index/worker work and P01 whole-product performance calibration are separate. No claim is made for physical low-performance devices, Safari, original Cherry/50 MiB Host corpora, or newly calibrated latency budgets. The new browser tests establish correctness on Chromium; the existing frozen P01 measurements are not replaced or presented as measurements of this implementation. Resource sync still hashes supplied bytes, and dirty detection compares snapshot fingerprints; these costs remain candidates for measured optimisation.
