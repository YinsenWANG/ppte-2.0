# PPTe 总反馈与实施方案：单文件直开、自由设计、快速生成、理解图片

版本：single-file-first 1.1 · 2026-09-06 · **待开发与验收，不是完成声明**。

本方案汇总用户本轮四项反馈和 [ea260ce 独立审查](../audits/2026-09-06-html-first-6091c9a/REPORT.md)。本提交以 `ea260ce678019c4e88c0ff3a9db4867a311e0b59` 为父历史，保留该报告、样稿、探针与证据。

执行入口：[任务与验收清单](TASKS.json)、[远程 Codex 交接指令](HANDOFF.md)。本方案优先于旧 HTML-first 方案中相冲突的默认启动方式、保存推荐入口、文件命名与 Skill 描述；没有冲突的安全、保真、编辑、放映、按需 PDF、证据要求继续有效。旧报告不改写，旧任务的 done 不构成本轮自动通过。

## 1. 本轮产品决定

**同一个 `作品.ppte.html`，既是演示文稿，也是编辑器和放映器。** 用户拿到文件，在支持的浏览器中直接打开即可查看、编辑、放映；机器上可以没有 Node、没有 PPTe 安装、没有服务进程，也可以断网。NPM 与原生 Skill 服务于制作和增强，不成为读者使用作品的前提。

|用户反馈|决策|完成的可观察结果|
|直接打开单文件就能用|以 `file://` 为主入口；自包含编辑与放映运行时|复制唯一成品到另一目录/另一台未安装 PPTe 的电脑，离线打开、改字、撤销、放映；不启动 HTTP 服务|
|审美提示应轻量|模型直接设计 HTML/CSS；Skill 只给一小段提醒|不生成设计规则库，不固定版式/卡片数量/字体白名单，不按美学分数阻断交付|
|速度仍慢|分别优化生成链路和使用时响应，先测量、再消除重复工作|报告真实用户等待时间、tokens、输入响应与保存时间；不能拿增强器几十毫秒代替整体速度|
|理解和使用用户图片|视觉理解进入选材、叙事和版式决策；支持无损裁切调整|确实看过图片，能把图片和页意图对应起来，主体与关键文字不被误裁，修改后仍可保存与再编辑|

默认交付一个 `.ppte.html`。这仍是普通 HTML 后缀，不恢复旧 `.ppte` ZIP/IR 格式；已生成的 `.html` 继续可打开，不擅自重命名或重写用户文件。PDF 仅由用户显式导出；不默认产生第二份编辑器、ZIP、PDF、图片目录或项目侧车。

保持 NPM + 原生 Skill，不增加 MCP stdio、第二个模型账号、QuickJS、Electron、常驻后台或浏览器扩展依赖。开发期间浏览器测试工具可用，但不能进入作品使用前提。

## 2. 先纠正事实，再纠正架构入口

`6091c9a` 的成品已经内嵌 `installEditor`、`workspace`、放映与保存适配代码，并非一个完全没有编辑器的静态网页。实际问题是直开时顶栏隐藏、启动按钮透明，Skill 又推荐 `ppte edit` 的 loopback 路径；用户最终感受到的是“文件只有内容，编辑器在服务里”。这是审查 F01 与默认产品路线共同造成的。

上一版方案第 5 节确实把 NPM 本地服务写成推荐保存入口。本轮用户明确要求单文件直开优先，因此在此**撤销该推荐策略**，不是声称远程实现从未遵循过旧文档。已有浏览器编辑核心应复用，避免重写整套编辑器。

目标分工：

```text
制作时：用户材料 → 当前 Agent 理解文字与图片 → 原生 HTML/CSS
       → NPM 一次增强/资源封装 → 作品.ppte.html

使用时：浏览器直接打开 作品.ppte.html
       ├─ 阅读 / 编辑 / 撤销 / 放映 / 按需打印（内嵌同一运行时）
       ├─ 获浏览器文件权限：写回选定原文件 + 自动保存
       └─ 无写权限或无 API：仍可完整编辑 → 下载包含修改的完整文件
```

运行时 UI、样式、脚本、资源均在文件内，不 fetch localhost、CDN 或另一编辑器。内容仍使用一份持久 DOM/CSS；编辑 UI 与作者 CSS 隔离。阅读可见简洁顶栏，进入编辑显示上下文工具，进入放映再隐藏编辑器。不要用“保持阅读像素一致”作为隐藏所有阅读入口的理由；保真比较应比较内容画布区域。

`ppte edit file` 改为便利的“用默认浏览器打开本文件并退出”，不再隐式监听端口；帮助和迁移说明写清行为变化。旧保存服务可留作开发工具/显式高级可选能力，但不能作为默认分发运行依赖、主界面按钮、缺少权限时的必经步骤或直开验收替代物。不为本轮新增系统文件关联或协议处理器。

## 3. 保存：独立编辑与自动覆盖原文件是两种能力

单文件内嵌编辑器完全可行；任意浏览器零授权自动覆盖磁盘原文件不能承诺。File System Access 的文件选择/写权限受浏览器、上下文和用户操作限制，API 存在也不等于实际授权成功；应检测实际能力并走真实授权旅程。[Chrome 文件访问说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[MDN 文件保存选择器](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)

### 3.1 统一交互，不把权限限制变成服务依赖

|状态|用户看见什么|操作结果|
|首次直开|名称、阅读/编辑、放映、保存；“尚未关联写入文件”|可以立即编辑，不先弹授权窗，不先要求安装|
|支持文件写入，首次点击保存|说明“选择当前文件以启用自动保存”并打开系统选择器|验证选中文件身份及基准内容，申请写权限；取消后修改仍在|
|已授权并有修改|有修改 → 保存中 → 已保存到文件|输入停顿约 800 ms 后串行写入；完成 close 和读回验证才确认|
|不支持写 API / 权限被拒|“当前浏览器不能覆盖原文件”；主操作“下载更新后的文件”|导出当前完整 `.ppte.html`，含编辑器、所有内容与内嵌媒体，不要求启动服务|
|下载已发起|“已生成更新文件；原文件未覆盖”|不得称为原文件自动保存成功；无法确认浏览器下载落盘时也不虚报已落盘|
|存在外部修改/另一窗口冲突|保留当前修改，展示冲突|提供重新读取、保留/下载当前版本；不自动覆盖或静默合并|
|草稿空间不足/私密浏览限制|“草稿恢复不可用；请保存或下载”|仍能编辑与导出，不声称有可靠恢复|

有权限时，“保存”与 Cmd/Ctrl+S 写回已绑定文件；“另存为”在更多菜单。无权限时同一保存动作解释限制并提供完整文件下载，不能只有一个难发现的“保存副本”按钮。下载通常可能得到浏览器追加编号的名字，不能承诺网页控制用户下载目录或覆盖策略。

### 3.2 实现约束

- 复用一套 SaveController，按能力接入 `FileHandleAdapter` 或 `DownloadExporter`；下载不是返回假成功的写文件 Adapter。分别维护 dirtyRevision、confirmedFileRevision、exportedRevision。
- 文件选择必须在直接用户动作里启动；昂贵的序列化可在选取成功后执行。绑定目标时验证文档身份与基准摘要，不靠文件名判断同一文件。无关文档拒绝绑定，另存为使用明确分支。
- handle/权限不写入成品。可用的浏览器本地存储仅作便利缓存；每次重开检查权限，必要时重新选择/授权，不能假设权限永久有效。
- 保留串行写、版本确认、冲突检测、IME 合并、失败保留和撤销历史语义。浏览器检查摘要与覆盖之间不是跨任意外部进程的原子比较交换，需记录这一边界，不以测试中的顺序执行宣称强事务。
- 普通保存保留文档身份；显式另存为建立新的文件实例身份。浏览器草稿键结合可获得的本地文件上下文、文档身份和基准摘要；复制/移动/同名文档不可仅凭 documentId 自动恢复另一份草稿。不确定时让用户选择是否恢复。
- `file://` 下 localStorage 行为没有跨浏览器统一保证，IndexedDB/OPFS 也不等于磁盘原文件。恢复状态必须做能力检测和失效测试。[MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)
- 完整下载序列化必须经过同样的内容清理和资源封装；不包含选区/光标、临时 blob URL、文件句柄、授权令牌、编辑工具 DOM。重新打开下载文件时依然可编辑和放映。

本轮接受的明确边界是：**直开编辑/放映在目标浏览器成立；自动写回只在实际支持且已授权的路径成立；其余路径有真实完整下载。** 不为追求“所有浏览器都自动覆盖”重新引入必需服务。若将来坚持所有浏览器静默自动覆盖，将是新的产品取舍，不能暗中实现。

## 4. 美学：一段提醒，保留模型的设计空间

拟写入 Skill 的审美提示仅用下面这一段，具体措辞允许压缩：

> 把美学当作作品质量的一部分：让每页重点明确，保持克制并善用留白；通过大小、位置、粗细与对比建立层级；注意对齐、间距、节奏与平衡；让字体、颜色和图形语言整体一致。结合内容自由设计，这些是提醒，不是必须套用的模板或硬规则。

不为审美新增模板选择阶段、配方 JSON、全页评分、固定字数/字号/卡片数、固定配色、预置主题强制覆盖或多轮自动“优化”。可以有安静、密集、全图、对照、叙事等不同页面节奏，模型按材料与受众选择；一致不意味着每页长得一样。

正确性检查与审美区分：丢事实、文字不可读/被裁切、图片失真、内容无法保存属于功能失败；不因为“没有三栏”或“用了非推荐颜色”失败。编辑器自身仍按既定 UI 与可访问性设计实现，不把对成稿的自由创作误解为产品控件可以随意。

旧同模型人工比较保留为产品质量评估，放在开发验收中；不把九对盲评或评分阈值塞入每次生成的 Skill。负责人本轮反馈是有效样本，不冒充已经完成整套盲评。

## 5. 性能：同时缩短制作等待与编辑响应

### 5.1 已知证据与待测假设

上一轮实际增强耗时约 61–78 ms，成品约 318 KB，现行全套测试约 54 秒。那个会话还同时做安装、代码审查、故障复现与报告；不能把全部会话时间称为生成时间，也不能拿增强器很快否认用户等待很久。

代码中可定位的候选开销：`workspace.ts` 每次命令变化调用 refresh/全量 thumbs，后者重新克隆所有页面；`save.ts` 的 schedule 每次立即执行完整内容草稿序列化并同步写 localStorage；原生 input 与 Commands.changed 都可能通知保存；资源封装对重复资源存在重复读/编码机会。这些是优化假设，先记录调用次数、耗时、主线程阻塞和字节量，不虚报已测得它们占比。

### 5.2 生成路径

1. 复用已安装 Skill、构建产物、工具和可用浏览器，不每次安装、全量构建、跑发布测试或重新下载字体。
2. 独立文字材料读取、已授权图片元数据读取与本地缩略图预处理可以有界并行。内容有依赖的叙事/选图/版式不盲目拆成互相不知道上下文的独立生成。
3. 模型直接写完整 HTML/CSS，一次增强，一次必要的全稿检查；需要时做局部修正。常规修正预算沿用最多一次的快速路径，仍失败则如实报告，不无限重写。
4. 缓存已验证的不变本地材料、缩略图和压缩结果。键包含内容摘要、变换参数、工具版本；视觉解释还包括当前任务意图与识别版本。权限/root 校验不能因缓存命中跳过。改变文件字节或需求必须失效，缓存不跨无关项目泄漏。
5. 只回传路径、页数、错误定位与摘要，不把整稿或 Base64 多次回流模型。仓库验收/发布门禁与用户日常生成分开运行，既不遗漏版本测试，也不让每次制作承担全量测试。

### 5.3 编辑运行时

- 维护 ID → DOM 的索引，插入/删除/替换时更新；不每次命令全树线性找节点。DOM/CSS 仍是内容事实源，索引不是新的展示 IR。
- dirty 标记带页面/节点范围。保持工具栏 DOM 和焦点稳定，只更新受影响字段；输入法与选区不因刷新被重置。
- 缩略图只更新改变的页面；可见区优先，空闲时处理其余页。不得仅用隐藏真实页面来虚拟化并破坏测量、放映和 PDF。
- 合并同一次编辑的重复通知；输入路径只标脏，草稿持久化按短延迟合并，文件写入约 800 ms 防抖。同步 localStorage 不再承载每个按键的整稿；异步存储按能力选用，失败降级透明。降低持久化频率必须同时记录未持久化窗口，不能悄悄扩大丢稿风险。
- 对同一 revision 的规范化内容/序列化结果复用，保存前后的实际磁盘摘要检查不得用缓存替代。保存未完成时产生新修改，旧回执不能清除新 dirty 状态。
- 大媒体字节与编辑操作元信息分离，撤销记录引用稳定资源身份，不能每次拖动都复制大段 Base64。保留恢复与撤销所需资源后再清理，不无限保留历史。

### 5.4 测量与门槛

先在固定真实参考机和一台真实较低性能设备冻结环境，报告 cold/hot、安装/材料理解/生成/增强/检查/修正/总时间，以及模型真实 tokens、调用数、失败与重试。图片预处理、视觉输入和解码单列；没有遥测填 unavailable，不用 HTML 长度估算 token。

保留原有同模型九对对照：热总耗时中位数目标 ≤ 直接 HTML 的 1.25×，tokens ≤1.20×；首稿、失败、尾部全保留。这是产品验收门槛，不是单次创作硬约束。新增图片稿单列比较，不能和纯文本平均后掩盖慢路径。

使用时记录首次可见/可编辑、输入到下一帧、翻页、缩略图更新、序列化及落盘时间。初始工程目标：12 页轻资源稿在参考机输入响应 p95 ≤50 ms、翻页 p95 ≤100 ms，原文件保存停顿到确认 p95 ≤1.5 s（包含防抖）；采至少 30 次输入/翻页与 10 次保存，原始记录可取回。长稿和图片稿单列，不通过删图片、缩小事实文字或关掉持久化过线。真实低性能设备报告相对本轮基线改善和失误，不以 CPU 限速模拟冒充实机；参考机未冻结前不填写通过。

## 6. 图片与多媒体进入内容理解

### 6.1 两层职责

**创作时 Agent 负责看懂与选择，浏览器内嵌编辑器负责可视调整和可靠保存。** 使用当前模型已有的视觉工具，不为作品读者增加云端 AI 调用或 API key。普通图片插入/裁切在断网时可用；离线 HTML 不承诺自己运行大模型理解图片。用户后来上传的新图片，Agent 有任务上下文时可继续理解并局部修改；只在浏览器中插入时提供手动裁切与布局能力。

### 6.2 从一批附件到有意图的选图

|步骤|动作|交给下一步的信息|
|资源清点|识别实际上传文件、格式、尺寸、方向、摘要、重复项；尊重“必须使用/不要使用”的指示|稳定 asset ID 与本地路径，不用文件名猜内容|
|视觉查看|少量图直接看；较多图先看带稳定编号的联系表，再看候选原图、图表和文字细节|主体、表达、场景、关键文字/数据、可裁区域、清晰度与不确定处|
|叙事匹配|先明确各页要表达什么，再选择支持该观点的图|页意图 ↔ 选图 ↔ 展现理由；可不选无关图，不强塞全部附件|
|图文设计|模型决定主图/背景/对照/细节图等角色，规划版式和必要裁切|原生 img/video/SVG 和 CSS，保持视觉主体与文字关系|
|实看复核|核对编号与真实图一致、裁切没丢主体/关键文字、放映和 PDF 清楚|对受影响页局部调整，不为一个图片重生成整稿|

图片较多时按视觉输入能力分批、有界处理，每张被选用的图都必须实际视觉查看；不能只看第一张就称已理解全部。如果不能逐张看完整批，应记录覆盖范围和选择限制。OCR/文件名只能辅助，不能代替视觉。看不清的图表数值、人物身份、产品型号不猜测；关键内容缺失时请求必要澄清，其他可独立工作继续。

临时选图笔记可以保留在工作缓存，格式自由，只保存有用的短说明；**不新增要求模型填满几十字段的媒体 schema 或固定步骤回执**。程序资产索引是可选资源管理元信息，不是另一套场景描述语言。

拟加入 Skill 的媒体提醒：

> 用户提供图片时，先实际查看并理解图片，再结合整稿内容选择与排版；关注主体、表达、图中文字和适合的裁切，避免机械插入或遗漏关键区域。不清楚的内容不要猜，保留可继续调整的图文关系。

### 6.3 裁切与内容保护

- 默认保持比例，使用 object-fit/object-position 或等效容器裁切，提供“完整显示/填充/焦点调整/重置裁切”。默认无损布局裁切，不破坏唯一原始像素。
- UI 截图、图表、文档、海报中的关键文字和数据优先完整显示或使用清楚的局部放大；不要用随机 cover 裁切。人物/产品图保留重要主体，压图文背景时保证文字对比。这里是内容正确性，不限制创意版式。
- 替换图片后重新评估比例、焦点与语义标签；不沿用导致新主体被裁掉的旧裁切。插入、替换、裁切、撤销/重做与保存重开走同一命令机制。
- 自动缩放仅用于适当的显示尺寸；有损压缩或会影响可读性/大幅减少原始分辨率的处理先呈现影响并按用户意图处理。原始上传文件不可覆盖。联系表是理解辅助，不把低清联系表裁块当最终图片。
- 所有关键使用资源最终内嵌；删除原素材目录后成品仍可用。不能依赖本地绝对路径、网络链接或仅在当前会话有效的 blob URL。

### 6.4 大图片不会重新拖垮单文件

第一步先测量图片占用、重复编码、解码和历史内存。对重复使用/历史中的大图，采用文件内轻量资源表：每个资源按摘要存一份字节和 MIME，DOM 对象保存稳定资源引用与裁切 CSS。旧 data URL 文件可继续读；小稿无需被强制重封装。资源表不储存另一份页面几何或内容镜像。

打开时可信运行时按需生成 blob URL；保存时持久化资源引用与字节，不保存临时 URL。为 img/media 精确允许所需 blob 能力，不放宽内容脚本或网络权限。打印和演讲者预览复制时必须持有资源生命周期，等图片解码和打印结束后再释放；这部分若未验证，不允许切换成新默认封装。

同一图片不同裁切复用同一资源；替换创建新身份，旧资源在撤销/恢复仍引用时不能提前清除。按资源/历史总容量设可见上限，超限明确提示。单文件传输本身需要包含所用图片字节，这个成本不能靠缓存数字掩盖；分别报告原始媒体、派生媒体、HTML 和 gzip 体积。

优先复用宿主已有图片读取工具与浏览器解码/裁切。基本文本生成不引入重图像依赖；确需额外编码器时按需安装并复用。格式能力由实测决定，不能把无法解码的 HEIC/损坏图静默省略。视频使用同一资源身份，提供封面、原生播放与离页暂停；按帧理解可在有用时由 Agent 做，不扩张成完整视频剪辑系统。

### 6.5 图片专项验收

准备经授权并留存的真实混合材料：人物/团队、产品图、UI 截图、图表、竖图、透明 logo、重复文件和不相关图片，至少 12 张；另有一组较大图片用于压力测试。记录文件摘要、测试意图与人工核对结果，不能用虚构的用户图片反馈。

验收者检查：选图是否支持页观点、主体是否保留、关键文字/数据是否可读、是否扭曲或重复堆砌、是否看过所用图；并实际执行替换不同宽高比图片、调整焦点、重置裁切、撤销、保存、重开、离线放映和 PDF。图表读错、关键区域丢失、原素材损坏或重开缺图为独立失败。其余构图偏好通过用户评价改进，不设必须选满多少张的硬指标。
