## 已确认的目标

单个 .ppte.html 直接打开，默认阅读，可编辑、放映；NPM + 原生 Skill。只插入图片；更多菜单移除，直接显示导出为 PDF。保存可靠优先于功能广度。

用户进一步确认：PDF 不依赖系统打印功能，视觉保真与文字可选择、搜索都必须保留。整页图片 PDF 不合格；不能为了导出限制 AI 为固定模板或退回第二套文稿模型。不能默默增加本地服务、上传文稿到云端或自动安装重量级运行环境。

## PDF：先解决真实的架构边界

|路线|判断|
|---|---|
|window.print 系统打印|不满足最新要求，不能继续作为产品 PDF 动作或失败兜底|
|HTML→整页图片→PDF|即使外观过关也丢失原生文字，排除作为交付路线|
|图片上覆盖透明文字/OCR|字形、选区、顺序可能错位；不作为满足原生文字要求的捷径|
|浏览器内 DOM→矢量/文字 PDF|可做有边界的验证，但没有证据证明现有库能通用复现任意 HTML/CSS；字体、中文排版、效果与布局覆盖是关键风险|
|受控 Chromium 直接生成 PDF|优先做质量对照样本；可避免系统对话框并控制页面参数，但仍使用浏览器 PDF/打印管线，需要页面外运行环境，不能冒充普通单文件页面已具备此能力|

依据：[html2canvas 文档](https://html2canvas.hertzen.com/documentation)明确其从 DOM 重新绘制且 CSS 支持有限；[pdf-lib](https://pdf-lib.js.org/)提供文字、图片、图形与字体写入，不等于 HTML 布局引擎；[Puppeteer Page.pdf](https://pptr.dev/api/puppeteer.page.pdf)说明默认 print 媒体、可切 screen 媒体并控制颜色。上述能力不证明某条路线已经通过本项目实测。

**推荐先验证受控 Chromium 的视觉与文字质量作为上限对照，同时验证一个浏览器内矢量候选。不能承诺当前“普通浏览器离线单文件、任意原生 HTML、无打印依赖、文字与视觉均保真”已存在成熟闭环。** 若仅外部渲染路线通过，需要明确交回用户决定是否接受独立可选导出工具；它不能变成阅读、编辑、放映的依赖。若用户拒绝架构变化，该项保持未完成，不交付假合格 PDF。受控 Chromium 路线也必须说明仍有浏览器打印管线，不能偷换“不依赖系统打印”的含义。

### 有边界的验证任务 F04A

最多比较两条候选：一个浏览器内矢量导出候选、受控 Chromium 对照。先检查字体嵌入、中文与 CSS 覆盖，明显不满足即可提前淘汰；不无限换库，不开发通用 CSS→PDF 引擎。

输入固定为：已认可的 UI 原型中实际文稿内容、10 页 Cherry 稿，以及覆盖中文多行/中英混排/嵌入字体/缺失字体、Grid/Flex、SVG、透明图、裁切、渐变/阴影、不同页面尺寸与复杂变换的夹具。UI 本身不导出。

每条候选交回可打开 PDF、逐页屏幕参考与 PDF 渲染对照、文字提取与人工选区记录、失败页、耗时/内存/体积和新增依赖成本。现有色彩正负样本保留；不同缩放与视口导出同稿应一致。文字既要能搜索，还要无乱码、复制顺序合理、选区贴合可见文本；不把提取出几个关键词当验收通过。字体不可访问或不可嵌入时必须明确记录，不能静默换字体后宣称保真。

先冻结参考稿与机器/浏览器版本，再比较同一输入。任何关键文字丢失、截断、错误换行、图片漏失或控件混入都失败；像素差异还需区分抗锯齿与布局偏差，人工认可不能由宽松阈值替代。

### 实现合同 F04（仅在路线通过后）

1. 点击“导出为 PDF”导出整稿，只交付一个 PDF，不自动附带 HTML，不弹系统打印窗口。不添加质量/纸张/边距等复杂设置菜单。
2. 捕获明确修订的完整编辑事务，隔离导出副本，不改变用户页码、模式、焦点、撤销栈或未保存状态。处理中提供进度与取消，防重复任务。
3. 按作者页面尺寸及规范视口渲染，与编辑器缩放无关；等待实际渲染上下文的字体、图片就绪。动画导出稳定最终态，视频使用明确封面，备注与所有编辑控件排除。
4. 逐页处理并释放中间资源，避免每页克隆整份文稿；共享只读资源并缓存字体处理，限制峰值内存。记录新增包与字体体积，不静默放宽现有预算。
5. 失败指出出错页/原因并可重试，不能下载缺页 PDF 或自动转系统打印。取消清理资源，编辑与保存可继续。
6. 离线 file:// 与声明支持浏览器逐项验证。外部工具通过只能证明外部工具路径，不能把 HTML 内入口标为通过。

当前 `packages/html-print/src/index.ts` 每页复制整个 documentElement 后删除其他页；以第一页尺寸承载所有页；内容移入 ShadowDOM 并重设样式；最后调用 window.print。字体等待使用外层 document.fonts。前者带来随页数放大的复制成本，后几项是需要验证的保真风险。不能只更换最后一个调用就宣布解决。

## 除已确认删减之外的进一步建议

以下为本轮建议范围，远程先落实既有明确要求；额外产品能力移除在交接中单列，不把建议伪装成用户已经逐项确认。

|建议收敛|留下的核心体验|
|---|---|
|独立演讲者弹窗、跨窗口同步入口|当前页、前后翻页、Esc 退出；放映无悬浮菜单，已有备注内容不删除|
|旋转数值、容器边距、复杂布局/保护开关等常驻属性|选中文字显示必要样式；选中图片显示替换、尺寸/裁切等稳定操作；内部内容保护仍保留|
|多套恢复/另存入口，复制整份 HTML 到剪贴板|一处保存状态、一条明确恢复流程；有恢复草稿时让用户预览并恢复，不冒充已写回文件|
|无入口仍后台自动创建的历史快照|保留已有数据与会话撤销，暂停新历史生成，减少体积及序列化负担|
|新建空页、重排、复制等未经真实 UI 验证的页面动作|先保留导航；页面管理若稳定可保留，若不稳定先下线，不继续扩大布局编辑器|

不删正文内容、已有形状/表格/SVG/媒体，不削弱 AI 原生 HTML 表达力；减少的是面向人工编辑的脆弱控件。已有安全链接 B2 与多行编辑 B1 仍是待修缺陷，不能借删菜单免除。

## 必须打磨的六条闭环

1. **文本：**点击选中、进入编辑、多行 Enter、中文输入法、退出编辑、撤销重做、保存重开完整走通。避免拖动/全局快捷键抢输入；B1 优先修。
2. **图片：**选择→解码→可理解的放置→选中→移动/调整→替换/非破坏裁切→撤销→保存。取消无变化；不支持布局的动作不显示成可用。数据只嵌入一份可复用资源，不能每次改尺寸重编码整图。
3. **保存：**单队列/修订号；失败不清 dirty，不自动下载。磁盘写入、浏览器恢复草稿、下载三者明确；原生授权与重开必须实测。当前已有队列/冲突检测应保留，不能为跑分删掉安全验证。
4. **恢复：**当前 save.ts 会全量序列化草稿并同步写 localStorage，持续编辑时约 200ms 检查点可能放大大图文稿负担。按修订复用结果、合并输入、减少同步全量写；评估可用的异步存储，但实测 file:// 的隔离、容量与恢复，不能假设所有浏览器都支持。交代恢复窗口，不能靠少备份掩盖性能问题。
5. **导航与 UI：**默认阅读、当前页居中、缩放只影响工作区、属性区不盖内容；统一图标、间距、hover/focus/disabled、错误与进度。状态始终一处，保存成功不抢焦点。真实键盘/触控与窄屏测试，不只截图。
6. **性能与生成：**保留已实现的按需媒体、局部缩略图更新及修订缓存；优先消除全稿重复克隆、同步存储、图片重复编码及不必要后台历史。生成保持 AI 直接写 HTML，再一次增强/验证；验证失败只修相应页，不反复整稿再生成。美学提示保持轻量，统一视觉语言而非硬模板。无依据不引入 QuickJS 或新重框架。
