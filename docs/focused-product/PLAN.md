# 功能收敛方案：图片、可靠保存、PDF

2026-09-07 · 用户实机反馈后的新决策 · proposed，未实现。

## 优先级与范围

本方案是当前最高优先级的产品范围，取代 UI 1.1、保存/历史方案和旧审查中与之冲突的功能广度要求。保留单 HTML、默认阅读、编辑、纯净放映、原生 HTML/CSS、离线使用、保存可靠性及内容保真。NPM + 原生 Skill，不引入必需服务或 Office/MCP stdio。

用户明确要求：插入只保留图片；更多菜单其他选项全部去掉，一级直接显示“导出为 PDF”；先确保少数能力足够好用，再打磨整体 UI。旧原型只保留视觉语言与三模式参考，不能继续照搬其完整菜单。

|旧要求|新决策|
|---|---|
|插入文本框、形状、表格、其他媒体|从当前产品入口、快捷键、上下文菜单和提示中移除，不迁移到另一个隐藏菜单|
|统一多项插入菜单|改为单个“插入图片”按钮，点击直接选择本地图片，不增加一层只有一个选项的菜单|
|更多菜单/通用操作列表|移除，原位置放“导出为 PDF”直接动作|
|版本历史、容量管理、无历史下载、新文件副本等可发现入口|当前界面移除，不再作为本轮新增交互交付目标，也不改名挪到保存菜单重新堆叠|
|已有图片、文本、形状、表格和媒体内容|继续正确阅读、放映和保存；删除插入能力不等于删除文稿内容，也不代表重写作者HTML|
|已有文件历史数据|不默默丢弃；保存兼容旧文件，默认暂停自动新增历史，避免无管理入口时继续增长；损坏/未知格式保持安全处理|
|保存失败兜底下载|保留为保存流程内用户明确选择的备选，不作为额外常驻长按钮|
|撤销/重做|保留当前编辑会话内纠错能力；不等同于历史版本管理|

停止扩展版本历史 UI；若以后需要恢复，另行确认范围。已有审查证据不改写，旧四类插入/版本UI测试应标注因用户范围变更而退休或迁移，不以删除测试宣称它们原本已经好用。

## 收敛后的界面

阅读顶栏：文稿名称、阅读/编辑、导出为 PDF、放映。编辑顶栏增加“保存”及一处简短状态；第二行只保留撤销、重做、插入图片及必要页面操作。底栏只保留页码、翻页、适应与缩放。放映始终只显示文稿，无悬浮菜单。

文本基本编辑、图片操作、页面导航保持可用。属性按对象显示，优先保留用户可理解的文字样式与图片尺寸/裁切；默认隐藏几何/CSS参数、重复按钮和缺少稳定行为的高级设置。已有非图片对象不强加一个工具全集：可保留验证过的操作，其余准确界定能力，不提供虚假控件。

不增加替代“更多”的菜单。保存面板只服务文件写入、状态与失败恢复，不收纳其他产品功能。原型的中性色、紧凑分组、清晰图标与留白继续沿用，功能数量按本方案减少。

## P1：把插入图片做好

流程：插入图片→系统选择器→适当位置呈现→明确选中→可移动/排列、缩放与非破坏裁切→撤销/重做→保存重开。

- 文件取消无副作用；失败保留原稿，明确格式/解码错误。不因选择图片重生成整稿。
- 保留图片原始比例，使用合理初始尺寸；主体与关键文字由生成时模型理解，浏览器端提供可调整裁切，不假装离线自动运行视觉模型。
- 根据当前页真实容器放置；不落在无留白的左上角，不遮挡重要文字，不把整个页面改成绝对定位。找不到可用放置方案时准确反馈，不能插入一个不可选、不可动的对象。
- 为不同作者布局提供真实可用的移动/顺序/对齐方式，界面不得宣传实际返回 LAYOUT_UNSUPPORTED 的动作。
- 验收覆盖横图、竖图、透明图、较大图片、连续插入、替换和不同裁切；使用真实鼠标/键盘，不用内部命令成功代替UI。

保留 S06 按需解码/离页资源释放和保存保真要求，不为了少功能退回重复加载整稿图片。

## P2：保存优先成为可靠的主流程

### 用户体验与状态

|情境|要求|
|---|---|
|首次直接打开|默认阅读，无授权要求；进入编辑不先弹权限窗|
|未修改|保存状态安静，不显示无意义错误|
|编辑后尚未关联|显示“有修改未保存”；点击保存后解释首次需选择当前文件授权；支持时给出“选择当前文件并保存”|
|能力不支持|说明此浏览器无法直接写回，提供“下载更新后的文件”；用户明确点击才下载，不把它叫已保存原文件|
|已关联且授权有效|保存或快捷键直接写回；默认自动保存完整编辑事务，合并连续修改|
|正在保存|显示正在保存；可继续编辑，成功只确认对应修订，最新改动未落盘仍保持未保存|
|写回成功|显示“已保存”与可查看的时间/文件名，以真实写入完成为准|
|取消/拒绝授权|保留修改和编辑现场；不自动下载，不反复弹窗，不把取消渲染成程序异常|
|权限失效/写入失败|清晰说明尚未保存，提供重试/重新授权或明确下载；错误不会瞬间消失|
|外部修改或选错文件|暂停写回，防覆盖其他文稿；提供可理解的恢复选择并保留当前内容|
|关闭前仍有修改|浏览器允许时提醒；不能依赖卸载时异步写入一定成功|

取消、权限拒绝、文件选择与文件读取/写入失败是不同状态，不统一吞成“未授权”。当前 `packages/html-editor/src/index.ts:79–113` 在能力不足、部分权限失败时调用 download，需改为显式选择分支；这来自代码检查，不冒充所有原生浏览器已实测。

### 正确性要求

一个保存队列、递增修订号，自动/手动共用清理序列化逻辑。单次写入期间的新内容排队，旧快照不能覆盖新快照；失败不改变上次成功基线。IME、拖动、多行输入按完整事务保存。先修 b93ffed 的 B1（Enter 后文本宿主失效），否则“保存成功”无法证明编辑可用。

首次选中的文件必须验证文档身份/内容基线，不能只比文件名。重开后检查真实权限，不能将已记住文件名当已授权。未知历史等旧数据不能因菜单删掉而在保存中被静默抹掉；本轮默认不再创建新的历史快照，避免无可见管理入口的额外体积和写入工作。

工作内容、浏览器恢复草稿和磁盘文件三者明确区分。浏览器缓存无法写入时不影响手动文件保存；显示故障时说明哪一层失败。下载结果必须自包含、默认阅读、可再次编辑；不输出多个默认文件。

### 不能再用模拟测试替代的验收

至少在一个支持的桌面浏览器真实执行：双击 file://→编辑文本和图片→系统选择器选择原文件并授权→保存→检查磁盘内容→关闭整个浏览器→重开确认。再验证自动保存、拒绝、撤销/失效、取消、选错文件、写入失败/冲突、新修改排队。用支持情况记录其他浏览器；不支持则实际走明确下载分支。

没有原生证据时保持“待验”，不能把桥接磁盘、headless下载、接口存在或全套绿灯当作这项已完成。本地验收环境无法完成的部分由远程组织目标机执行，不因困难引入必需本地服务。

## P3：一级“导出为 PDF”

用户最新要求覆盖此前系统打印路径：不依赖系统打印；视觉保真与文字可选择、搜索均必须保留。整页图片 PDF 不合格，不能静默降级或引入必需服务。

先执行 F04A 有边界技术验证，再选择实现路线。技术边界、对照样本、文字与视觉验收、性能及额外功能收敛建议见 [PDF-AND-CORE-REVIEW.md](PDF-AND-CORE-REVIEW.md)，该补充为 PDF 最新合同。受控 Chromium 仅作质量对照，不能冒充单文件页面可直接调用；外部工具若成为唯一可行路线，需交回用户决定架构取舍。

产品入口目标仍为阅读/编辑中直接导出整稿，一个 PDF、进度与取消、原稿现场不变。路线未通过时准确标待完成，不用系统打印、图片 PDF 或删除验收要求充数。

## P4：在减法之后打磨 UI

按单一组件样式重新整理顶栏、编辑条、页面栏、属性区、保存状态和PDF入口；不得只是隐藏旧菜单后留下空位或失效快捷键。常用动作简短、图标可辨识，有名称和焦点状态；统一按钮尺寸、间距、圆角、色彩与错误反馈。低频技术信息不常驻。

桌面当前页居中，属性展开不裁切；小屏属性限高不盖住画布。长稿页面栏独立滚动，新建页不能被缩放栏挡住。原型作为视觉参考，不要求保留已废弃功能，也不通过缩小文字塞入所有控件。

提交1440/1024/390同稿截图与真实操作证据，明确与原型相比保留了哪些优点。最终UI与成稿美学分别由用户确认；未确认不填写人工passed。

## 远程执行与发布门槛

顺序：范围清理→保存与B1→图片闭环→整稿PDF→UI打磨→真实旅程复验。B2安全引用链接的合同差距、性能/媒体和其他非冲突可靠性问题继续保留；不借范围收敛清空缺陷。

发布至少满足：无废弃入口；文本与图片编辑稳定；原文件保存/自动保存有实际目标机证据或明确标待验；下载兜底经过用户选择；整稿PDF正确；唯一HTML重开可用；界面用户确认。功能缺口按项标明，不把“少了按钮”当成完成。
