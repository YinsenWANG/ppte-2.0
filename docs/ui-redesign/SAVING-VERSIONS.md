# 原文件保存、自动保存与版本历史

版本：saving-versions-1.0 · 2026-09-07 · 新增设计，待实现与验收。

本补充承接 [UI 设计](DESIGN.md) 和 [单文件方案](../single-file-first/PLAN.md)。保存与自动保存属于原有目标的明确化；跨关闭、重开的版本历史是新增范围。这里的条款优先于冲突的旧保存/历史描述；其他审查问题继续有效。历史审查报告和原型测试结果不改写。

## 产品合同

用户交付仍是一个 `.ppte.html`，直接打开默认阅读，可编辑和放映，不要求 Node、HTTP 服务、MCP stdio、云账号或额外应用。文件写入能力根据实际浏览器与权限分级，不能由此取消编辑功能。

目标支持路径：用户通过原生选择器明确关联并授权目标文件后，点击“保存”或 ⌘/Ctrl+S 写回该文件；自动保存默认开启。首次双击打开不能被解释为已授权写回。能力不足、授权撤销或取消时，完整下载是明确的兜底，不是原文件写回。

文件内版本历史随文件移动，不依赖浏览器缓存。浏览器草稿只辅助恢复；会话内撤销重做、自动保存与持久版本历史是三个不同机制。

## 保存 UI 与状态

编辑顶栏主操作统一叫“保存”，相邻状态可点击展开保存面板。未修改的阅读界面不催促保存。

|状态|界面与动作|
|---|---|
|编辑产生修改，未关联文件|“修改尚未写入文件”；保存面板提供“关联文件并保存”和“下载更新后的文件”。若浏览器不具备前者能力，准确说明并只提供可用路径|
|请求授权|用户主动点击后启动系统选择器，取消不丢修改，不反复自动弹窗|
|已关联，等待合并写入|“有修改”；自动保存开关开启时按下述节奏执行|
|写入中|“正在保存…”；仍可继续编辑|
|最新修订写入成功|“已保存 · 时间”；只有写入完成且内容修订号匹配时可出现|
|授权失效/失败|“尚未保存”；保留修改，提供重试、重新授权、下载；重要错误不一闪而过|
|下载兜底|“已发起下载，原文件未覆盖”；禁止自动清除原文件未保存状态或显示已写回|
|恢复缓存草稿|“已恢复本机草稿，尚未写入文件”；先展示恢复选择，不无声覆盖文件内容|

保存面板包含文件名称、关联状态、自动保存开关、最近成功时间与下载备选。不要在菜单里出现句柄、adapter 等工程词。自动保存开关只控制写回调度，不停止用户主动保存，也不关闭草稿恢复能力。

关联时验证用户选中的文件：与打开时文档身份及已知基线进行检查；不同文档不能直接覆盖。用户若希望另存为，应通过明确的“保存到其他文件”流程并确认目标，而不是凭同名认定为原文件。文件内只存文档身份，不存文件路径、句柄或权限信息；它们不是文档交付数据。

## 自动保存与并发正确性

- 使用单一保存控制器，统一自动保存、手动保存、下载和版本打包，避免各自实现序列化清理逻辑。
- 以内容修订号标识工作状态。参考调度：输入停止 1 秒后保存；持续输入时最多等待 10 秒尝试保存完整事务。IME 组合输入、拖动和表格批处理结束后再提交，不保存半个操作。
- 手动保存优先提交当前完整事务；同一时刻最多一个写入。写入期间的新修改合并为下一次，不启动并发文件写入，不让旧快照覆盖新内容。
- 从修订 r 开始保存后，即使写入成功，只能确认 r；如果已编辑到 r+1，仍显示有修改并排队保存，不能误标最新内容已保存。
- 写入成功以实际写入流完成为准；失败保留上一次基线和当前工作内容。重新授权后再次检查外部变化，不能直接把旧队列写回。
- 保存前检查文件与最近成功基线是否发生外部变化。发现冲突时暂停自动写回，提供“查看磁盘版本”“下载我的修改”等明确选择。无操作系统级排他锁时不能承诺绝对消除检查与写入之间的竞争；须说明并测试支持环境边界。
- 重开后恢复关联信息仅在浏览器实际支持且权限有效时启用自动保存；否则由用户重新关联。检测能力不能只判断函数存在，需结合成功/拒绝返回和原生操作证据。
- 关闭页面时仅执行浏览器允许的最佳努力，不依赖卸载时异步保存一定完成；有未写回内容时提供允许的离开提醒。

调度数字是初始实现参数，需根据 S04 数据调整。1 秒防抖等待与实际序列化/写入时长分开统计，不通过把等待排除后宣称端到端达标。大媒体文件避免每次键入重复编码和哈希；缓存按内容修订失效，在空闲或 Worker 中进行可移出的处理，继续现有性能预算。

## 版本历史 UI

从更多菜单进入“版本历史”，编辑模式可创建/命名/管理版本；阅读模式可查看。版本面板显示时间、名称、来源（自动/手动/恢复前）、是否已写入文件。版本预览在独立只读区域中呈现，不改当前内容，不退出当前未保存状态。

提供“保存命名版本”“预览”“恢复到此版本”“删除版本”；不默认导出一堆备份文件。“版本”是内容状态，不是每次撤销栈项。首次运行时可将首次编辑前内容作为起始版本；只有写入或下载完整文件后才成为持久历史。

恢复操作前显示目标时间，并明确“当前内容会先保留一个版本”。成功后历史保留原目标版本，当前内容成为新的修订，记录恢复来源；不能将文件倒退后删掉后续历史。若恢复前快照无法被安全保留（容量、资源损坏等），先解决或让用户下载当前内容，不静默丢弃。恢复结果仍需实际保存，未授权时显示尚未写回。

## 版本生成与容量规则

自动保存不等于自动产生新版本。初始规则：发生内容变化时，每 5 分钟最多创建一次自动版本；手动命名、恢复前创建明确版本；内容摘要相同则去重。版本快照以完整事务为边界，不含编辑选框、工具 DOM、临时 blob URL 或嵌套运行时。

初始预算：保留最近 20 个自动版本；历史额外存储预算 16 MiB（不含当前内容必需资源）。这两个值为可调整默认值，需要在含大媒体材料上实测，不是美学规则。超预算先回收最旧的未命名自动版本。命名版本不自动丢弃；仍超预算时暂停新增历史并显示可操作提示，允许删除旧版本或调整上限。**当前内容的保存不能因历史配额满而被无声阻止，现有命名历史也不能被静默删掉。**

开启历史容量管理应显示历史占用与清理范围。删除历史为跨会话的不可恢复动作，确认时注明影响版本数量；删除当前内容引用的资源被禁止。历史只包含用户选择保留的内容；提供“下载不含历史的文件”，避免发送文件时连已经删除的旧内容一并分享。它是显式按需操作，默认仍只交付一个文件。

## 单文件存储与恢复协议

HTML/CSS 仍是内容事实源；版本存储只是同一内容的记录，不引入新的演示 IR。建议使用带 schemaVersion 的惰性读取数据区：文档 ID、当前内容修订、版本索引、内容快照/差量块、共享资源表。每个版本包含 id、时间、名称/类型、父版本或检查点引用、内容摘要与资源引用。

优先复用 S06 媒体去重：资源按摘要只存一份，历史引用资源 ID。新增历史不重复嵌入整份编辑器脚本，也不重复存相同图片。采用差量时必须有周期性检查点；裁剪旧版本前重建仍依赖它的链路，不能删基版本导致后续不可恢复。可先实现去重的完整内容快照再优化差量，但必须通过容量、打开速度和恢复正确性门槛。

启动只读取当前内容和轻量索引；打开版本面板或预览时才解码所需历史，不能启动即解码全部图片、重建全部旧页。共享资源存储模式不能重新在当前 DOM 中多份展开大 data URL；与尚未完成的 S06 按需解码/生命周期工作合并。

版本数据作为不可信输入处理：校验 schema、摘要、引用、尺寸和解压上限，正确转义内嵌脚本结束标记等特殊内容。预览隔离且不执行历史里的任意脚本，不为预览引入更宽权限；恢复走现有导入与保存安全边界。

历史损坏时仍应能打开完整的当前内容，并准确提示哪些版本不可恢复；未知历史格式不能静默丢弃后覆盖原文件，先保持原数据或下载副本。测试包含截断数据、缺失资源、断链和异常大数据。

## 执行清单

在 UI04 下完成写回、调度、状态与并发；新增 UI07 负责持久版本历史；UI06 总验收依赖 UI07。同步更新单文件 S02/S06/S07/S08 的证据引用，但不要把新任务置为 done。

|验收组|必须记录的证据|
|---|---|
|原文件保存|从 file:// 原生选择目标、允许写入、实际修改磁盘文件、退出浏览器、新进程重开仍保留内容；检查未选文件不被改动|
|自动保存|停顿输入、持续输入、IME/拖动、写入期间新修改、手动与自动竞争；最后磁盘内容等于最新完整修订|
|权限与失败|取消、撤销、重授权、只读/写入失败、外部改动、退出时未完成；状态真实，修改可恢复|
|下载兜底|不支持或拒绝授权时，完整下载可离线重开；不把下载当原文件保存|
|跨会话历史|创建两个不同内容版本和一个命名版本→保存→关闭整个浏览器→新进程打开→预览/恢复→再保存；保留恢复前状态|
|可携带历史|将唯一文件复制到另一目录与独立浏览器/设备，禁用原浏览器缓存后仍可查看与恢复历史；没有目录旁备份文件依赖|
|容量与资源|重复图片不重复累积；裁剪不破坏差量链或命名版本；资源回收保留所有仍被引用的内容；清理历史后当前内容不变|
|安全与故障|恶意/损坏历史不执行脚本、不导致无界解压、不阻断当前文稿阅读；无历史下载不残留旧内容资源|
|性能|记录实际保存、版本创建、首次打开、预览、恢复耗时与文件大小；使用真实媒体和现有 S04 基线对照|

原生权限必须有人实际操作或等价真实系统自动化证据；mock、桥接 API 和 headless 下载测试不能替代。按浏览器分别记录支持、通过、失败、pending，尤其 file:// 下的句柄存储与重开授权；不要求不支持的浏览器虚构原生写回通过。

## 浏览器参考

能力背景见 [Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access) 与 [MDN showSaveFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)。它们支持权限分级的设计依据，不是本项目 file:// 路径已经通过实测的证明。
