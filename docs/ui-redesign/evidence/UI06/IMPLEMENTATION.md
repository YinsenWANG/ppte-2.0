`tests/ui06-acceptance.test.ts` 在构建后的 dist 中运行三个 node:test：

- A1/A2：当前生产运行时离线 file:// 默认阅读 → 编辑 → 用统一菜单插入文本、形状、本地 PNG、表格并修改属性 → 两个命名版本 → 实际下载 → 完整关闭 Chrome → 只复制唯一 HTML 到另一目录 → 全新进程、空 localStorage 阅读 → 只读预览验证四类对象 → 在未保存编辑之后恢复并验证恢复前快照 → 再下载 → 第二次完整退出、第三个进程重开 → 纯净放映及 Esc → PDF。精确比较完整内容，检查图片原始宽度/裁切焦点、形状颜色、单元格内容和原文件哈希，全部进程记录网络和脚本错误。通过 PDFKit 独立检查 Chromium PDF 的页数、尺寸和文字。PDF API 不等于原生打印对话框。
- A3：环境记录合同测试要求 Safari、原生权限、系统 IME、打印、屏幕阅读器与独立设备缺失结果为 null、有原因和后续操作步骤，不允许接口桥接冒充原生权限。**这是记录完整性测试，不是这些环境通过的证明。** 实际 Chrome 产品结果另见 journey.json。
- A4：分别验证 product-ui 与 sample-aesthetics 两份记录。负责人、两名目标用户评分/评语均为 null；九对、事实/裁切/保存否决保持未评估。**记录合同通过不代表用户评价通过。** 不改写历史用户意见。

首轮全旅程实测发现：共享资源表的 4096 字符门槛使小 PNG 在当前内容及三个检查点中重复四份。修复 `packMedia`：所有受支持的 base64 媒体均按内容摘要共享，不再按大小跳过。保留图片仅出现一次的原断言，初次失败日志归档；未弱化现有断言。传统无资源表输入仍由原管线读取，不重编码图像、不改 CSP、不引入服务或新的格式。修复不覆盖 SVG/CSS 资源或 S06 当前 DOM 按需解码。

样稿源为 `tests/fixtures/ui06/journey.html`：两页作者 HTML/CSS，纸白与绿色，Grid 内容容器，四类对象由产品控件插入。不是移植原型坐标模型，不是受控 Skill 制稿/九对盲评。生成 PNG 是功能性图像，不冒充真实用户图片批。截图检查确认两页内容可见、布局无截断；该检查属于代理观察，不是审美人评。主交付文件在 `../delivery/把作品带走.ppte.html`，随文件含第一稿、第二稿及恢复前内容；SHA-256 在 delivery/manifest.json。
