## U02：图片直接操作，取代参数式调整

### 状态与动作

|状态|用户可做的事|反馈|
|---|---|---|
|插入|单个“插入图片”直接选文件|解码期间轻量进度，可取消；完成后当前页中可见并选中|
|选中|拖动图片；拖四角等比缩放；方向键微调|清晰边框，四角手柄；图标旁有短标签；不显示 CSS 数值面板|
|裁切|双击图片或点“裁切”；拖动原图移动主体，拖裁切框边角调整可见范围|框外半透明显示原图；明确“完成”“取消”|
|退出|Enter 完成裁切，Esc 取消当前裁切；点击外部结束普通选中|取消恢复进入裁切前状态；不会误删图片|
|替换|单个“替换图片”选择文件|保留框的位置与尺寸，新图按比例居中；可重新裁切|
|删除/撤销|显式删除或编辑状态下 Delete；撤销/重做|一次完整拖动/裁切记一个事务，不是每像素一步|

四角可见手柄约 8–10 CSS px，鼠标有效命中区至少 24px，触控至少 44px；命中区随工作区缩放仍可操作。光标准确，拖动捕获指针，画布滚动/窗口缩放后坐标正确。文本输入或输入法组合期间不抢快捷键；阅读/放映不能调整。

普通选中只提供“替换、裁切、删除”；尺寸通过拖动调整，去掉图片的 x/y、宽高数值、object-position 百分比、旋转/边框等面板入口。本轮不提供多选图片批量布局功能。不要把复杂参数挪到更多菜单。

### 布局实现边界

新插入图片建立页面局部、可保存的图片框，位置使用作者页面坐标，原图与裁切框分离；不重写整页为绝对定位。框内保留原始图像资源，裁切非破坏，重复调整不反复编码图片。拖动不能让图片完全丢出页面且无找回方式。

已有 Grid/Flex/正常流图片：拖动前提供明确位置预览；实现可保持原布局的排序/移动适配。若自由移动需要脱离原布局，应保留原占位并局部建立图片框，验证兄弟内容不重排或跳动；不能显示可用手柄后返回 LAYOUT_UNSUPPORTED。该适配未通过的作者结构必须准确报告，不能宣称任意 HTML 都可自由拖动。变换、裁切、保存清理共用同一作者坐标与序列化模型。

先使用竖图放入横向框验证主体移动与缩放，再覆盖横图、透明图、小图、较大图及四类布局。真实指针操作后撤销、保存、关闭、重开逐项比对；内部命令成功不是验收。

## U03：保存成为可理解且可验证的主流程

### 主路径

顶栏一个主动作及一处状态：能写回的浏览器显示“保存”；未建立关联时首次点击解释“首次保存需要选择当前文件”，再通过明确按钮发起系统选择器。用户完成授权后写入并回读，状态才变“已保存 · 时间”；后续默认自动保存。无需先找到“保存状态”里的操作。

不支持直接写回时，主动作直接显示“下载更新后的文件”，旁边简短说明“此浏览器不能覆盖原文件”；点击后只下载一个完整 HTML。它是有边界的可用兜底，**不能替代原文件保存任务的验收**。取消或拒绝时不自动下载。

保存状态点开只展示当前文件、最近成功时间、必要的重试/重新关联；去掉“复制恢复草稿”“复制保留当前修改”等复制整份 HTML 的技术动作，去掉常驻磁盘预览和多套另存入口。恢复问题出现时才展示恢复流程，不作为工具全集。

### 状态与异常

- 未改动：安静显示，不把尚未授权当错误警告。编辑后：有修改未保存。
- 保存进行中：可以继续编辑；只确认对应修订，新修改仍排队。合并完整编辑事务，IME 中不写半成品。
- 取消/拒绝/失效：保留编辑现场，明确还未保存，用户点击后才重新授权；不循环弹窗。
- 选错文件/磁盘被外部修改：暂停写入，保留当前稿；按需展示磁盘稿预览，提供重新选择或显式下载当前稿。不得静默覆盖。
- 发现恢复草稿：说明时间与来源，预览后“恢复”或“保留文件版本”；恢复前保留当前内容，取消不丢数据。恢复不等于落盘。
- 缓存满/不可用：说明自动恢复不可用，但手动保存继续；不要把草稿故障混成文件保存故障。
- 关闭：浏览器允许时提示未落盘修改，不能依赖 unload 异步写回。

### 先定位再修，不能虚构原因

在实际桌面 Chrome 直接打开新成稿副本，记录保存入口是否可发现、实际能力、选择器/权限、选择后目标、磁盘变化、状态与重开结果。优先用现有可调用桌面工具执行；若远程没有桌面通道，完成代码、自动化和可操作交付文件后，回交本地执行原生步骤，不能无限堆 pending 报告或声称只能等用户修复。

至少证明一次原文件手动写回和一次自动写回，随后退出整个浏览器再打开同一文件，文字与裁切仍在。拒绝/取消、同名错文件、外部冲突、保存期间新修改、失败重试分别验证。记录操作视频/截图、文件前后摘要及正文，模拟句柄证据单列。Safari/内置浏览器按实测能力显示兜底，不猜测通用支持。

性能：保留单队列、基线/冲突与回读确认；复用修订序列化，合并草稿写入。用带较大图片的真实稿检查输入卡顿与存储失败，不能通过删除恢复保障来优化数字。

## U04：PDF 阻塞项继续定位，不把禁用按钮当交付

用户要求仍为不依赖系统打印、视觉保真、文字可选择/搜索，三项必须同时成立。禁止整页图片、透明文字层/OCR 充数、偷偷启动服务或上传。当前两个候选失败的记录完整保留。

本轮先诊断已验证的受控 Chromium 候选，不扩大为漫无目的选库：
1. 用同一个失败 PDF 在 PDFKit 与另一个现有独立阅读/解析器对照中文混排、搜索和选区，定位是生成结果、阅读器排序还是测试预期。
2. 复杂变换的视口差异对照固定作者视口，区分抗锯齿与真实位移，检查导出适配是否引入偏差；不得降低既定要求掩盖差异。
3. 在现有路线内修复适配后重跑原失败夹具及全部20页，输出对照 PDF 和结论；没有现成工具时记录缺口，不自动安装重环境。

即使 Chromium 质量通过，它仍是外部浏览器 PDF 管线，不是普通离线 HTML 内可直接调用的能力。先交回质量证据和运行依赖，由用户决定是否接受可选工具等架构取舍；不能直接进入产品集成。若仍失败，明确尚无合格路线与具体原因。本轮允许上述原路线诊断，解除“验证失败后完全不能继续定位”的解释，但不授权新服务、无限候选或自研通用 CSS 引擎。

架构未定前 PDF 继续标未完成；不默认移除用户需要的功能，也不称整体可发布。
