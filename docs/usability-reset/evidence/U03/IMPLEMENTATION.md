# U03 — 保存主流程重做

用户报告“保存基本不可用”仍为实机体验事实，具体失败路径未定位。本轮不是用旧绿色测试关闭拒收。实现与自动化可验，原生系统授权和用户体验不宣称通过。

## 实现

- 编辑顶栏按实际 API/安全上下文能力显示一个“保存”或“下载更新后的文件”。不支持时旁边说明不能覆盖原文件；明确点击下载只产生一个完整 HTML，dirty 与原文件确认修订均不因此清除。
- 初次保存先解释“首次保存需要选择当前文件”，再由明确按钮打开选择器；显示实际路径末尾文件名帮助定位。匹配文档身份、内容、修订及历史，写入、关闭、回读确认后显示“已保存 · 时间”。首次成功关闭面板，不挡住后续操作。
- 普通状态面板仅显示当前文件和最近成功记录；错误才提供重新选择/明确下载，冲突才提供磁盘预览和读取。删除复制整份 HTML 的两种按钮、常驻磁盘预览、自动保存开关及重复另存入口；默认自动保存保持开启。正常未编辑保持安静。
- 保留原单写队列、回读、外部变化检测、修订缓存及 IME/完整事务边界。未关联时不调度无意义的文件 flush；首个草稿仍立即尝试，正常持续编辑合并为 200ms 检查点。已知缓存失败后持续编辑的缓存重试退避至 2s；手动保存、页面隐藏和关闭检查点仍即时尝试，不删除恢复数据。
- 草稿发现后显示时间/来源，先预览再恢复。保持文件版本不修改正文；恢复前内容在会话及可用缓存中保留，提供“返回恢复前内容”。最新草稿优先于保留副本；成功写入仍不会删除另一窗口的草稿。恢复不冒充落盘。损坏草稿与缓存配额错误不再冒充文件写入故障。
- 磁盘预览使用解包后的作者正文，避免直接把无可见正文的自包含运行时放进禁止脚本的 iframe。

## 旧测试迁移（没有删除安全/正文断言）

- S02、F01、F02、UI04：首次保存增加明确关联按钮点击。无 API 的“保存不下载”旧动作已被 U03 改为直接下载；原未操作/取消/拒绝不得自动下载断言保留，新 U03 补“显式主按钮恰好一个下载”。
- 通用下载 helper 在没有失败下载选择时显式模拟无 API 能力，测试后还原；这是模拟能力测试，不是 Safari 证据。
- UI04 移除开关 UI 后，保留控制器 auto-off/queued/manual 断言，另断言默认开启与开关不再出现。
- H02/S01 初次状态改为安静，原未关联限制断言继续检查 controller.detail，并增加 pristine 检查。重开不能假称本次已写入，改断言“未改动”以及 confirmedFileRevision=null；正文、磁盘和重开断言原样保留。
- H02 loopback 恢复也改成显式预览/恢复，保留恢复后的正文和磁盘自动写入断言。F05 保留下载按钮文字断言于准确的无 API 能力分支，增加支持浏览器正常状态没有第二下载动作的断言。

## 实测发现与限制

- 首轮全仓测试发现首次保存后面板挡住“页面设置”，已修复并保留失败日志；其余首轮失败是状态/入口合同迁移遗漏，已补迁移而非忽略测试。
- 大图夹具最初直接双击跨越属性面板展开造成的工作区变化，选中容器而非文本；改成先单击选中、稳定后双击输入，保持真实键盘和完整文字断言。此既有首次双击命中问题没有在 U03 范围中宣称修复，需在图片/工作区实机回归继续检查。
- 大图片日志记录自然 localStorage 配额不足、输入往返和 longtask。存在数百毫秒级主线程任务，不能称“大稿流畅”。缓存退避减少已知失败的重复写入，没有消除全稿序列化/工作区刷新的成本；用户流畅度仍待确认。
- `screenshots/` 全部为 Chrome headless file:// 自动化截图；`journeys/` 的磁盘写入采用模拟 FileHandle + Node I/O，不是原生授权。未启动新增服务、未上传、未安装环境；全仓既有测试自身包含已授权测试用临时 loopback fixture。
- 没有可调用桌面工具。已有 osascript 的只读 System Events 探测挂起未返回，主动停止；这不证明权限被拒绝，也不证明原生文件 API 不可用。具体步骤见 NATIVE-VALIDATION.md。

## 交付文件与边界

`Cherry-U03.ppte.html` 仅升级既有 Cherry 文稿的运行时，正文/历史保持原样，无测试文字或测试图。它是 U03 原生保存验证载体，**不是新美学成稿，不是 U01 全稿生成**。U01/U04 停机门及 PDF 架构均未触碰。本任务整体保持 reopened，不能整体发布或验收通过。

附：缓存退避测试发现未关联时原 1s 文件 flush 仍会提前重试草稿；取消这条无可写目标的定时分支后，2s 退避与显式手动重试均由真实控制器测试覆盖。失败日志 `verification/backoff-gate.log` 保留。重新读取磁盘也调整为挂载成功后才更换基线/清 dirty，读取/挂载失败不会提前清除未落盘标记。
